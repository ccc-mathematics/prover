## 3.6.1 怎麼讀這份紀錄

每個快照有兩種成分：**上下文**（`名字 : 命題` 的清單，即 $\Gamma$ ）與**目標**（`⊢ 命題`，即待證的 $A$ ）。中間那行 `⊢` 是分界線；`⊢` 上方是手上有的，下方是還差的。

有一個現象要先解釋清楚，因為它貫穿全部八個範例：**`cases` 與 `constructor` 產生的新目標，上下文會各自複製一份。** 例如 `and_swap` 的 `constructor` 之後，兩個目標各自帶著 `h`、`hp`、`hq` 三個假設。這是自然演繹的標準語意——兩個分支是兩條獨立的推理線——但在截圖裡看起來會有點囉嗦，因為同一個 `h` 被重複印了兩次。

## 3.6.2 and_swap：合取交換律

```
theorem and_swap : P ∧ Q → Q ∧ P
  intro h
      h : P ∧ Q
      ⊢ Q ∧ P
  cases h with hp hq
      h : P ∧ Q
      hp : P
      hq : Q
      ⊢ Q ∧ P
  constructor
      2 個目標
      
      h : P ∧ Q
      hp : P
      hq : Q
      ⊢ Q
      
      h : P ∧ Q
      hp : P
      hq : Q
      ⊢ P
  exact hq
      h : P ∧ Q
      hp : P
      hq : Q
      ⊢ P
  exact hp
      沒有目標了
```

逐行說明：

- `intro h`：目標是 $P \wedge Q \to Q \wedge P$ ，是蘊含。`intro` 把前提 $P \wedge Q$ 放進上下文，目標變成 $Q \wedge P$ 。證明項片段是 `impI`。
- `cases h with hp hq`：`h` 的型別是 $\wedge$ ，走 `cases` 的第一個分支。上下文多出 `hp : P` 與 `hq : Q`，**目標不變**。證明項片段是巢狀的 `let`。
- `constructor`：目標是 $\wedge$ ，拆成兩個目標 $\vdash Q$ 與 $\vdash P$ （注意順序：左半先解）。證明項片段是 `andI`。
- `exact hq`：目標 $\vdash Q$ 直接由 `hq : Q` 得到。證明項是 `hyp hq`。
- `exact hp`：目標 $\vdash P$ 由 `hp : P` 得到。

最後產生的證明項（把 `meta` 洞填滿之後）：

```
impI h  [前提 P ∧ Q]
  └ let hp
    ├ p = andE1 (hyp h)
    └ q = let hq
      ├ p = andE2 (hyp h)
      └ q = andI
        ├ hyp hq
        └ hyp hp
```

`let` 的兩層巢狀正是 3.4 節說的：核心的 `let` 規則把 `p.n` 綁進上下文才檢查 `p.q`，所以「`hp` 綁左半、`hq` 綁右半」必須用兩層 `let` 表達。

**這個範例的教訓**：`cases` 對 $\wedge$ 的處理是「把資訊攤平到同一條線上」，對 $\vee$ 则是「分成兩條線」。兩者產生的目標數目不同（1 對 2），這是使用者最常搞混的地方。

## 3.6.3 syllogism：假言三段論

```
theorem syllogism : P → R
  intro hp
      h1 : P → Q
      h2 : Q → R
      hp : P
      ⊢ R
  apply h2
      h1 : P → Q
      h2 : Q → R
      hp : P
      ⊢ Q
  apply h1
      h1 : P → Q
      h2 : Q → R
      hp : P
      ⊢ P
  exact hp
      沒有目標了
```

這是 3.1 節那張圖的實例。`intro hp` 之後，目標是 $R$ ；`apply h2` 問的是「要證 $R$ ，我手上有 $h2 : Q \to R$ ，還缺什麼？缺 $Q$ 」；`apply h1` 同理得到 $\vdash P$ ；`exact hp` 用上下文裡的 `hp : P` 結案。

證明項：

```
impI hp  [前提 P]
  └ impE
    ├ hyp h2
    └ impE
      ├ hyp h1
      └ hyp hp
```

這棵樹正是第 2 章那條 modus ponens 鏈，只是換成了 Curry–Howard 的樣子：`impI` 是 λ-抽象，`impE` 是應用，`hyp` 是變數。`impE (hyp h2) (impE (hyp h1) (hyp hp))` 讀成 $\lambda hp . h2 (h1 \, hp)$ ——**一個把 $P$ 變成 $R$ 的函式**。

## 3.6.4 or_comm：析取交換律

```
theorem or_comm : P ∨ Q → Q ∨ P
  intro h
      h : P ∨ Q
      ⊢ Q ∨ P
  cases h with hp hq
      2 個目標
      
      h : P ∨ Q
      hp : P
      ⊢ Q ∨ P
      
      h : P ∨ Q
      hq : Q
      ⊢ Q ∨ P
  right
      2 個目標
      
      h : P ∨ Q
      hp : P
      ⊢ P
      
      h : P ∨ Q
      hq : Q
      ⊢ Q ∨ P
  exact hp
      h : P ∨ Q
      hq : Q
      ⊢ Q ∨ P
  left
      h : P ∨ Q
      hq : Q
      ⊢ Q
  exact hq
      沒有目標了
```

這個範例把 `cases` 對 $\vee$ 的處理看得很清楚：`cases h with hp hq` 產生**兩個目標**，左支的上下文有 `hp : P`，右支的上下文有 `hq : Q`。兩個分支都必須證明**同一個**目標 $Q \vee P$ ——這正是核心 `orE` 規則的側條件（3.3 節）。

`right` 在左支選擇 $P$ 那一邊（`orI2`，因為目標是 $Q \vee P$ ），`left` 在右支選擇 $Q$ 那一邊（`orI1`）。注意證明項裡被放棄的那一半是直接寫在節點上的：

```
impI h  [前提 P ∨ Q]
  └ orE  x = hp , y = hq
    ├ hyp h
    ├ a = orI2  [另一支 Q]
    │  └ hyp hp
    └ b = orI1  [另一支 P]
       └ hyp hq
```

**注意 `orE` 節點上的 `x = hp`、`y = hq`**：這兩個名字是「分支裡的假設名」，核心用它們來把 $\vee$ 的兩半分別放進兩個分支的上下文。整個證明項裡，只有這裡需要分支專屬的名字系統。

## 3.6.5 dne：雙重否定消去（古典）

```
theorem dne : ¬¬P → P
  intro h
      h : ¬¬P
      ⊢ P
  by_contra hn
      h : ¬¬P
      hn : ¬P
      ⊢ False
  exact h hn
      沒有目標了
```

這個範例是全章的**第一個轉折點**。它用到 `by_contra`，而 `by_contra` 會產生 `dne` 節點——也就是 3.3 節說的、**直觀主義邏輯裡不可推導的那條規則**。

看清楚 `by_contra hn` 做了什麼：

1. 目標是 $P$ ，它建立一個否定 $\neg P$ （內部是 $P \to \bot$ ）。
2. 把 $\neg P$ 當作假設 `hn` 放進上下文。
3. 目標換成 $\bot$ 。
4. 證明項是 `dne (impI hn (¬P) (meta g1))`——也就是「先證明 $\neg\neg P$ ，再用 DNE 得到 $P$ 」。

然後 `exact h hn`：`h : ¬¬P` 這個假設本身就是 $\neg P \to \bot$ ，把 `hn : ¬P` 餵進去，得到 $\bot$ 。整個證明項：

```
impI h  [前提 ¬¬P]
  └ dne
    └ impI hn  [前提 ¬P]
      └ impE
        ├ hyp h
        └ hyp hn
```

**這棵樹裡的 `dne` 是整個 `lean-prover` 中唯一一個沒有 Curry–Howard 對應的規則節點。** 拿走它（把 `dne` 從核心刪掉、把 `by_contra` 從策略層刪掉），剩下的系統就是一個直觀主義的自然演繹證明器，而且除少數定理外照樣能用——只是 `dne` 與 `peirce` 這兩個定理會證不出來。

README 裡的這句話——「古典邏輯，`by_contra` 使用雙重否定消去規則」——就是這個設計的自我說明。它把古典性**集中到一個可見的點**上，而不是讓它滲透到每一條規則裡。第 6.3 節會討論「如果系統是直觀主義的，這兩個定理會怎樣」，第 8.2 節會討論「直觀主義到古典的完整代價是什麼」。

## 3.6.6 peirce：Peirce 定律（古典）

```
theorem peirce : ((P → Q) → P) → P
  intro h
      h : (P → Q) → P
      ⊢ P
  by_contra hn
      h : (P → Q) → P
      hn : ¬P
      ⊢ False
  apply hn
      h : (P → Q) → P
      hn : ¬P
      ⊢ P
  apply h
      h : (P → Q) → P
      hn : ¬P
      ⊢ P → Q
  intro hp
      h : (P → Q) → P
      hn : ¬P
      hp : P
      ⊢ Q
  exfalso
      h : (P → Q) → P
      hn : ¬P
      hp : P
      ⊢ False
  exact hn hp
      沒有目標了
```

Peirce 定律 $(\left(P \to Q\right) \to P) \to P$ 是「邏輯」最著名的例子之一，也是直觀主義與古典邏輯分歧最尖銳的地方之一。它常被寫成 Peirce 自己的版本 $\left((P \to Q) \to P\right) \to P$ ，跟蘋果的 slogan 押韻的那個 Peirce 是同名的兩位先生。

這個證明是整個系統裡最長的一個，值得逐行拆解：

- `by_contra hn`：目標 $P$ 變成 $\bot$ ，上下文多出 `hn : ¬P`。
- `apply hn`：`hn : ¬P` 就是 $P \to \bot$ ，所以「要證 $\bot$ ，我缺一個 $P$ 」。目標變成 $\vdash P$ 。
- `apply h`：`h : (P \to Q) \to P`，所以「要證 $P$ ，我缺一個 $P \to Q$ 」。目標變成 $\vdash P \to Q$ 。
- `intro hp`：目標變成 $\vdash Q$ ，上下文多出 `hp : P`。
- `exfalso`：目標變回 $\bot$ 。這是合法的——一旦手上有了 `hp : P` 和 `hn : ¬P`， $P$ 與 $\neg P$ 同時在手，矛盾已經成立，所以可以從 $\bot$ 推出任何東西。證明項是 `botE`。
- `exact hn hp`：`hn : ¬P` 吃 `hp : P`，得到 $\bot$ 。

證明項：

```
impI h  [前提 (P → Q) → P]
  └ dne
    └ impI hn  [前提 ¬P]
      └ impE
        ├ hyp hn
        └ impE
          ├ hyp h
          └ impI hp  [前提 P]
            └ botE  [結論 Q]
              └ impE
                ├ hyp hn
                └ hyp hp
```

**注意 `botE` 節點上的「結論 Q」**：那不是核心推導出來的，而是**由策略層放進證明項的**（`exfalso` 策略直接把當時的目標記在 `botE` 節點的 `f` 欄位裡，見 `lean.js:156`）。核心的 `botE` 規則只檢查前提確實是 $\bot$ ，然後直接回傳這個預先宣告的結論。這是 3.3 節提過的「核心回傳的可能是證明項自己宣告的東西」的情形——對爆炸律來說，這完全合理，因為 $\bot$ 可以推出任何東西，核心沒有辦法也沒有必要去推導那個結論。

`dne` 與 `peirce` 一起說明了本章的一個基本觀點：**它們的證明比直觀主義的對應命題要長，而且長在「多出一個 `dne` 節點」這個地方**。用戶寫 `by_contra` 的時候完全感覺不到自己在使用古典邏輯——古典性藏在 `by_contra` 這一個策略裡。

## 3.6.7 socrates：蘇格拉底三段論

```
theorem socrates : Mortal(socrates)
  exact h socrates m
      沒有目標了
```

```
theorem socrates (h : forall x. Man(x) -> Mortal(x)) (m : Man(socrates)) : Mortal(socrates) := by
  exact h socrates m
```

這是唯一一個**一行結束**的範例，而且它一次用上了 `app()` 的全部三種行為。

目標是 $Mortal(socrates)$ ，上下文有 `h : ∀x, Man(x) → Mortal(x)` 與 `m : Man(socrates)`。`exact h socrates m` 被 `app()` 拆成三步（3.4 節的表格）：

| 讀到 | 判定 | 動作 | 當前型別 |
|---|---|---|---|
| `h` | 起頭 | `hyp h` | $\forall x . Man(x) \to Mortal(x)$ |
| `socrates` | 不是假設（上下文裡沒有這個名字的假設） | 當成**項**，∀ 消去 | $Man(socrates) \to Mortal(socrates)$ |
| `m` | 是假設 | → 消去 | $Mortal(socrates)$ |

證明項：

```
impE
  ├ allE  t = socrates
    ├ hyp h
    └
  └ hyp m
```

`allE` 節點上的 `t = socrates` 就是代入全稱公式的項。核心的 `allE` 規則會用 `sub()` 把它代進主體（3.3 節）。

**這個範例是 3.4 節那個「名字空間共享」歧義的最好教材**：`socrates` 之所以被當成項而不是假設，純粹因為上下文裡沒有叫 `socrates` 的假設。使用者若寫了一個叫 `socrates` 的假設，這個證明就會以一種非常難懂的方式失敗。

另外注意：這個命題裡的 `Man` 與 `Mortal` 都是**零元的原子**（`Man` 而非 `Man(x)`）——系統不要求謂詞必須帶參數，這讓命題可以用接近自然語言的方式書寫。

## 3.6.8 all_and：∀ 對 ∧ 分配

```
theorem all_and : (∀ x, P(x) ∧ Q(x)) → (∀ x, P(x)) ∧ (∀ x, Q(x))
  intro h
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ (∀ x, P(x)) ∧ (∀ x, Q(x))
  constructor
      2 個目標
      
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ ∀ x, P(x)
      
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ ∀ x, Q(x)
  intro y
      2 個目標
      
      y : 項
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ P(y)
      
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ ∀ x, Q(x)
  have hy := h y
      2 個目標
      
      y : 項
      h : ∀ x, P(x) ∧ Q(x)
      hy : P(y) ∧ Q(y)
      ⊢ P(y)
      
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ ∀ x, Q(x)
  cases hy with a b
      2 個目標
      
      y : 項
      h : ∀ x, P(x) ∧ Q(x)
      hy : P(y) ∧ Q(y)
      a : P(y)
      b : Q(y)
      ⊢ P(y)
      
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ ∀ x, Q(x)
  exact a
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ ∀ x, Q(x)
  intro z
      z : 項
      h : ∀ x, P(x) ∧ Q(x)
      ⊢ Q(z)
  have hz := h z
      z : 項
      h : ∀ x, P(x) ∧ Q(x)
      hz : P(z) ∧ Q(z)
      ⊢ Q(z)
  cases hz with a b
      z : 項
      h : ∀ x, P(x) ∧ Q(x)
      hz : P(z) ∧ Q(z)
      a : P(z)
      b : Q(z)
      ⊢ Q(z)
  exact b
      沒有目標了
```

這裡有兩個新東西：**`vars` 欄位**與**`have` 的 `:=` 語意**。

`intro y` 之後，多了一行 `y : 項`。這是 3.1 節講過的：目標是 $\forall x . P(x)$ ，`intro` 把綁定變數 $x$ 改名成 `y`，得到 $\vdash P(y)$ 。為什麼要改名？因為一旦我們離開量詞， $x$ 就變成一個自由的項變數了，而它必須是**全新的**——否則就會和公式裡其他的 $x$ 撞名。`fresh()` 就是這道防線。

關於變數名：預設名是 `x`，在這個範例裡**其實是可以用的**——因為 `h` 裡的 $x$ 是**綁定**的，`fv(h) = ∅`，`fresh('x')` 檢查不過不了。使用者顯式寫了 `y`，而且第二個分支又用了 `z`。用不同的名字是好習慣：兩個分支本來在同一個目標上先後執行（`constructor` 產生兩個目標，先解左邊再解右邊），若兩邊同名，證明項讀起來會分不清哪個 `allI` 對應哪個分支。

`have hy := h y` 是 `:=` 語意：`h y` 是一個**已經成立的項**（它是對 `h` 做 ∀ 消去得到的），所以 `hy` 的型別 $P(y) \wedge Q(y)$ 是**算出來的**，不需要使用者寫出來，也**不需要一個新目標**去證它。快照顯示：目標從 $\vdash P(y)$ 變成 $\vdash P(y)$ （型別沒變），但上下文多了一行 `hy : P(y) ∧ Q(y)`。

對比 `have h : A` 語意：那一種會多產生一個「先證 $A$ 」的目標。兩者的差別在證明項裡看得很清楚：`:=` 的 `let` 節點左邊是**實體**（`allE (hyp h) y`），`:` 的 `let` 節點左邊是**洞**。

證明項片段：

```
impI h  [前提 ∀ x, P(x) ∧ Q(x)]
  └ andI
    ├ allI  v = y
      └ let hy
        ├ p = allE  t = y
        │  ├ hyp h
        │  └
        └ q = let a
          ├ p = andE1 (hyp hy)
          └ q = let b
            ├ p = andE2 (hyp hy)
            └ q = hyp a
    └ allI  v = z
      └ let hz
        ├ p = allE  t = z
        │  ├ hyp h
        │  └
        └ q = let a
          ├ p = andE1 (hyp hz)
          └ q = let b
            ├ p = andE2 (hyp hz)
            └ q = hyp b
```

**注意 `allI` 節點上只有 `v = y`，沒有「主體是什麼」。** 這與 3.3 節說的「證明項必須自足」形成一個有趣的對照：`impI` 節點帶著前提 $A$ （`f` 欄位），因為核心需要它來組合蘊含型別；而 `allI` 節點不需要帶主體，因為核心可以從子證明的型別反推—— $\forall v . B$ 的 $B$ 就是子證明的型別。

## 3.6.9 ex_not_all：∃ 與 ∀ 的對偶

```
theorem ex_not_all : (∃ x, P(x)) → ¬(∀ x, ¬P(x))
  intro h
      h : ∃ x, P(x)
      ⊢ ¬(∀ x, ¬P(x))
  intro hn
      h : ∃ x, P(x)
      hn : ∀ x, ¬P(x)
      ⊢ False
  cases h with x hx
      x : 項
      h : ∃ x, P(x)
      hn : ∀ x, ¬P(x)
      hx : P(x)
      ⊢ False
  exact hn x hx
      沒有目標了
```

這個範例把量詞與否定放在一起，是本專案裡最接近「邏輯學內容」的定理：**若存在一個 $P$ ，則並非所有東西都不是 $P$ **。

先要把目標的形狀算清楚。定理宣告是

```
theorem ex_not_all : (exists x. P(x)) -> ~(forall x. ~P(x))
```

回頭看 3.2 節的展開規則： $\sim A$ 在解析期變成 $A \to \bot$ 。所以整個結論的 AST 是

$$
(\exists x . P(x)) \to \bigl((\forall x . \neg P(x)) \to \bot\bigr)
$$

**裡面有兩層蘊含。** 而 `intro` 每呼叫一次就拆掉一層——這正是為什麼這個範例需要連續兩次 `intro`：

- `intro h`：目標是 $(\exists x . P(x)) \to (\ldots)$ ，`f.t === 'imp'`，所以把前提 $\exists x . P(x)$ 放進上下文，目標換成結論 $\neg(\forall x . \neg P(x))$ 。**這是第一個快照**。
- `intro hn`：目標 $\neg(\forall x . \neg P(x))$ 的 AST 是 $(\forall x . \neg P(x)) \to \bot$ ，`f.t` 仍然是 `'imp'`，所以把 $\forall x . \neg P(x)$ 放進上下文（名字 `hn`），目標換成 $\bot$ 。**這是第二個快照**。

順帶回答一個容易卡住的問題：目標是 $\bot$ 的時候 `intro` 會不會報錯？會——`is('all', '(需要 → 或 ∀)')` 會擋下來。但這個範例裡 `intro` 兩次都沒有遇到 $\bot$ 目標，因為那個 $\bot$ 是被**第二層**蘊含的結論換出來的。

現在繼續：

- `cases h with x hx`：`h : ∃x, P(x)` 是存在命題，走 `cases` 的第三個分支。上下文多出 `hx : P(x)`（`sub(A.f, A.v, { v: 'x' })` 把 $\exists x . P(x)$ 的主體 $P(x)$ 裡那個**綁定**的 $x$ 換成新的見證名 `x`），`vars` 多出 `x`，所以出現 `x : 項` 那一行。目標不變（仍是 $\bot$ ）。證明項是 `exE`。
- `exact hn x hx`：`hn : ∀x. ¬P(x)`。`app` 讀到 `hn`（假設），然後 `x`——**上下文裡沒有叫 `x` 的假設**（`x` 是一個項變數，出現在 `vars` 裡而不是 `ctx` 裡），所以被當成項，做 ∀ 消去，得到 $P(x) \to \bot$ 。再讀到 `hx`（假設 $P(x)$ ），做 → 消去，得到 $\bot$ 。✓

證明項：

```
impI h  [前提 ∃ x, P(x)]
  └ impI hn  [前提 ∀ x, ¬P(x)]
    └ exE  x = x , h = hx
      ├ hyp h
      └ impE
        ├ allE  t = x
        │  ├ hyp hn
        │  └
        └ hyp hx
```

**`exE` 節點上的 `x = x` 很有意思**：見證變數叫 `x`，與存在公式自己的綁定變數 `x` 同名。3.5 節解釋過這是安全的，因為 `fv(∃x. P(x)) = ∅`——綁定變數不算自由變數，所以核心的新鮮性檢查不會被觸發。

## 3.6.10 目標型別 → 該用哪個策略

把八個範例用過的策略攤開，得到一張「看到目標就該用什麼」的對照表：

| 目標的形狀 | 首選策略 | 其他可用 | 產生的新目標數 | 注意事項 |
|---|---|---|---|---|
| $A \to B$ | `intro h` | `apply`、`exact` | 1 | 前提進上下文 |
| $\forall x . A$ | `intro y` | `exact h t` | 1 | 需要**新**變數名 |
| $A \wedge B$ | `constructor` | `cases`（若已知有 $\wedge$ 假設） | 2 | 左右順序 |
| $A \vee B$ | `left` / `right` | `cases`（若已知有 $\vee$ 假設） | 1 | 只能選一邊 |
| $\exists x . A$ | `exists t` | `cases`（若已知有 $\exists$ 假設） | 1 | 見證必須吻合 |
| $\bot$ | `exfalso` | `by_contra` | 1 | 先證 $\bot$ |
| 任意 | `exact e` | `apply h`、`assumption`、`have`、`show`、`sorry` | 0 或 n | `exact` 要求型別完全吻合 |
| 任意 | `by_contra h` | `exfalso` | 1 | **古典**：會用到 `dne` |

再補一張「手上**有**假設時」的對照：

| 手上的假設型別 | 策略 | 效果 |
|---|---|---|
| $A \wedge B$ | `cases h with a b` | 1 個目標，上下文多出 `a`、`b` |
| $A \vee B$ | `cases h with a b` | 2 個目標，各自帶一支 |
| $\exists x . A$ | `cases h with a b` | 1 個目標，上下文多出 `b : A[a/x]` |
| $A \to B$ | `apply h` | 1 個目標 $\vdash A$ |
| $\forall x . A$ | `apply h t` 或 `exact h t` | 0 個目標（型別吻合的話） |

## 3.6.11 一個附帶的觀察：證明項的顯示

順帶一提，`runThm()` 產生的 `r.term` 是把證明項用 `sx()` 印成一個字串。它的結果對某些節點會顯示成 `[object Object]`：

```
(impI h ([object Object] and P) (let hp (andE1 h) (let hq (andE2 h) (andI hq hp))))
```

原因是 `sx()` 用 `v && v.r ? sx(v) : ...` 來判斷一個子欄位是不是「子證明項」，而 `imp`／`and`／`or` 三種**公式**節點剛好也有 `r` 欄位（蘊含的右operand、合取的右operand），於是被誤判成證明項拿去遞迴。`all`／`ex` 節點因為用的是 `f` 欄位，所以沒有這個問題（`ex_not_all` 的 `∃ x, P(x)` 就印得好好的）。

這是一個純粹的顯示問題，不影響核心檢查——`check()` 從來不看 `sx()` 的輸出。修法很短（判斷子節點是不是證明項時應該看有沒有 `r` **字串**欄位），但它提醒我們一件事：**這個系統裡「公式」與「證明項」兩種資料結構在欄位命名上高度重疊**（都用 `t`／`f`／`l`／`r`），任何依賴「看欄位猜型別」的程式碼都要小心。核心的 `check()` 之所以安全，是因為它的 `switch (p.r)` 明確列舉了所有合法的規則名，遇到不認識的就報錯——它從不靠欄位的形狀去猜。

## 3.6.12 小結與交棒

八個範例走完，整章的機制已經全部落地。回頭看，可以把本章濃縮成一句話：

> **證明是一棵資料結構；策略是它的生產者，每一步同時產生「帶洞的證明項片段」與「新的目標」；核心是它的守門員，最後把所有洞填滿、逐條規則驗證、回傳它證明的命題，再與宣告比對一次。**

這三層之間的分工，產生了本章最重要的那個性質：**策略層可以出很多錯，但錯誤證明過不了核心這一道關。** 這是 de Bruijn 準則（第 7.1 節）在本專案裡的完整實現。

也正因為如此，核心必須**小**。`check()` 大約三十行有效程式碼，剝掉解析器與策略層之後，它小到可以逐句唸出來確認每一個 `case` 對應哪條自然演繹規則。第 7 章會把這個「核心要小到可以審查」的工程問題正式提出來。

但在結束本章之前，還有一個問題沒有回答。

第 3.3 節的核心之所以能那麼簡潔，一個關鍵原因是 3.2 節的解析期展開： $A \leftrightarrow B$ 被展開成 $(A \to B) \wedge (B \to A)$ ， $\neg A$ 被展開成 $A \to \bot$ 。所有規則都只需要處理「一個前提、一個結論」的形狀。

**但如果連展開都不允許呢？** 假如邏輯裡有原子、連接詞、量詞，而我們希望有一套**完全自動**的證明搜尋——不需要人給思路，機器自己找矛盾——那麼規則的形狀就必須更容易被機器「反過來用」。這正是 Robinson 1965 年的歸結原理做的事：它把整個邏輯壓縮成單一的一條規則，反過來用就變成一個搜尋程序。

**下一章就是那條路。** 第 4 章將離開互動式證明器，走進 `theorem-prover`：看一套不需要使用者給任何想法、只靠子句化與合一就能自己找到矛盾的系統。請記住那個對照——**歸結法的核心規則比自然演繹的核心規則更少，但它換來的是「自動」這個特性**。
