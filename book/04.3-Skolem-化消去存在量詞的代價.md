# 4.3 Skolem 化：消去存在量詞的代價

第 4.2 節把公式壓成了子句，但有一個問題還懸著：`forall x. (Man(x) -> Mortal(x))` 轉出來的子句是 `~Man(X2) | Mortal(X2)`，變數 `X2` 是自由的。這沒有問題——**子句裡的變數本來就隱含全稱**，所以把 `∀x` 換成一個普通變數是語意中立的。

麻煩的是 `∃`。子句裡沒有「存在」的表達方式。要讓歸結法能推理存在性，就必須先把 `∃x` 從語言裡剷除，而這個剷除動作，就是 **Skolem 化**。

Skolem 化聽起來像個技術細節，實際上它是整個 ATP 世界觀的轉折點：它是**第一個不可逆的步驟**。NNF 與 CNF 都保留語意（可滿足性等價），從 Skolem 化開始，程式碼開始「猜」——猜一個見證者的形狀。

## skolem()：十一行做掉的事

```js
function skolem(f, env, us) {
  switch (f.t) {
    case 'all': { const v = fresh(); return skolem(f.f, { ...env, [f.v]: { v } }, [...us, { v }]); }
    case 'ex': return skolem(f.f, { ...env, [f.v]: { f: 'sk' + (++skn), a: us } }, us);
    case 'and': case 'or': return { t: f.t, l: skolem(f.l, env, us), r: skolem(f.r, env, us) };
    default: { const a = f.t === 'not' ? f.f : f; return { t: 'lit', s: f.t !== 'not', n: a.n, a: a.a.map(x => sub(x, env)) }; }
  }
}
```

（`theorem-prover/src/prover.js:60-66`）

三個參數各司其職：`f` 是還沒處理的公式，`env` 是「原變數名 → 新項」的對應表，`us` 是**依賴清單**——記錄目前公式外層還活著的、來自 `∀` 的全稱變數。

**`case 'all'`：消掉 `∀`。** 一個 `∀x` 被換成一個新鮮變數 `fresh()`（`theorem-prover/src/prover.js:46`，產生 `_1`、`_2` 之類的內部名稱），並且記錄 `x ↦ 新變數`。同時把新變數推進依賴清單 `us`。為什麼連 `∀` 都要消掉？因為子句裡的變數隱含全稱，所以 `∀x. P(x)` 與 `P(x)` 在子句層級是同一件事——把束縛變數換成自由變數，語意不變，但子句裡再也沒有量詞節點可以煩惱我們。

**`case 'ex'`：消掉 `∃`。** 一個 `∃y` 被換成一個 Skolem 項 `{ f: 'sk' + (++skn), a: us }`。`skn` 是全域計數器（第 45 行），保證每次呼叫都得到不同名字（`sk1`、`sk2`……）。關鍵在 `a: us`：**這個 Skolem 項的引數，就是它外層所有全稱變數**。這就是依賴清單的全部用途。

**`case 'and'` / `case 'or'`：** 結構照抄，兩邊共用同一份 `env` 與 `us`。

**`default`：** 終端是文字。`s` 記錄正負號（`not` 就是負），`n` 是謂詞名，引數則用 `sub(x, env)` 把原變數名換成新項（第 48 行）。從這裡開始，輸出不再是公式樹，而是**文字**——`cnf()` 期待的正是這個。

## 依賴清單：為什麼是 `sk1(x)` 而不是 `sk1`

現在來看整節最重要的一個例子。取公式 `∀x. ∃y. P(x, y)`，語意是「對每個 x，都存在一個 y 使 `P(x,y)` 成立」。

走一遍程式碼：`all` 分支把 `x` 換成新鮮變數 `_1`，依賴清單變成 `[_1]`；`ex` 分支看到 `us` 非空，於是建立 Skolem 項 `sk1(_1)`。輸出：

```
P(_1,sk1(_1))
```

如果 Skolem 化寫得偷懶一點，把 `∃y` 直接換成一個常數 `sk1`，輸出會變成：

```
P(_1,sk1)
```

兩者差在哪裡？差在 `sk1` 與 `x` 之間的依賴關係。正確的那一版說：「對每個 x，有一個**由 x 決定**的 y」。偷懶的那一版說：「有一個 y，對**所有** x 都行」。

而後者嚴格更弱。舉一個具體的反例。取一個只有兩個元素的集合（元素記為 0 與 1），定義 `P(x, y)` 為「y 是 x 的後繼」（模 2 加一）。那麼：

- 原式 $\forall x\, \exists y\, P(x, y)$ **為真**：給定 x，取 y = x + 1 即可。
- 偷懶版 $\exists y\, \forall x\, P(x, y)$ **為假**：沒有任何 y 能同時是 0 的後繼與 1 的後繼。

所以依賴清單不是可有可無的裝飾。Skolem 項必須依賴**所有在外**的全稱變數，少一個就會把一個存在命題偷換成一個更強（通常為假）的命詞。

順帶一提，實作裡 `us` 是**單純的清單**而不是集合，這意味著同一個變數如果被重複推入（例如巢狀的 `∀` 綁到不同變數但意外同名），會出現重複引數——但因為 `fresh()` 保證每次 `∀` 都產生不同名稱，實務上不會發生。

## 兩個 Skolem 化的實例

為了看見依賴清單的效果，最直接的方法是讓實作跑兩個例子。第一個是 `forall x. exists y. P(x,y)`，經過 `clausify` 之後得到：

```
P(X1,sk1(X1))
```

（顯示層會把內部的 `_1` 換成 `X1`，見 `theorem-prover/src/prover.js:201`。）注意 `sk1` 有一個引數——那個引數就是外層的 `∀x`。如果把 `∃y` 放到最外層，Skolem 項就沒有引數了。第二個例子是 `examples/barber.txt` 裡的理髮師悖論：

```
exists b. forall x. (Shaves(b,x) <-> ~Shaves(x,x))
```

它的 Skolem 化結果是兩個子句（`node bin/cli.js examples/barber.txt` 的實際輸出）：

```
~Shaves(sk1,X2) | ~Shaves(X2,X2)
Shaves(X3,X3) | Shaves(sk1,X3)
```

這裡 `sk1` 沒有引數，因為 `∃b` 前面沒有任何全稱量詞——依賴清單 `us` 是空的。這個細節在語意上是對的：理髮師是某個固定的人，與 `x` 無關。

把兩個例子並排看，就能看出依賴清單不是裝飾品，而是一個**結構性的參數**：`sk1` 帶一個引數，`sk2` 不帶，差別完全取決於 `∃` 所在的量化深度。

## Skolem 定理：等價的那一半

Skolem 化有一個標準的定理支持：

$$
\text{封閉公式 } F \text{ 可滿足} \;\Longleftrightarrow\; F \text{ 的 Skolem 形式可滿足}
$$

兩個方向的理由都不難。往右：給定 F 的一個模型，對每個 `∃` 選定模型中的一個元素當作 Skolem 函數在該點的值，就能得到 Skolem 形式的模型。往左：給定 Skolem 形式的一個模型，把 Skolem 項解讀成它代表的元素、把全稱變數解讀成全稱，就得到 F 的模型。

所以 **Skolem 化本身不會製造矛盾，也不會消滅矛盾**。它對「這組公式能不能同時成立」這個問題是中性的。

然而在實作裡，這個中性的轉換卻帶來一個極不中性的後果。原因不在 Skolem 定理，而在**推論系統的完備性**。要分清楚兩件事：

- **可靠方向成立。** 如果 Skolem 化後的子句集真的推出了矛盾（空子句），那麼原公式一定不可滿足，結論一定不成立。這是可靠的。
- **反向不成立。** 如果 Skolem 化後的子句集飽和了、沒找到矛盾，那麼**不能**斷言原命題為真。飽和只代表「在這個推論系統與這個搜尋策略之下，沒能找到矛盾」。

第二點跟 Skolem 定理並不衝突：Skolem 定理保證「可滿足性」這件事在轉換前後一致，但歸結法**無法證明一個公式是可滿足的**——它是半可判定的（semi-decidable）定理證明器。這正是第 4.1 節講過的「ATP 的失敗是語意上的空洞」。

這裡還有一層本實作特有的折扣：本章第 4.7 節會看到，參數替換（paramodulation）在改寫時**把等式從母句中丟掉**，而沒有項排序與化簡。這種做法在可靠性上安全，但在**完備性**上是打折的。因此在本實作裡，「飽和」甚至不能被解讀為「真的可滿足」——它可能只是「這個被削弱過的推論系統挖不出來」。

## 與 ITP 的對照：兩種處理量詞的哲學

第 3 章的 `lean-prover` 對量詞採取完全相反的做法。看它的兩條規則：

```js
case 'exI': return eq(C(p.p), sub(p.f, p.v, p.t)) ? { t: 'ex', v: p.v, f: p.f } : bad('∃ 引入的見證不吻合');
case 'exE': {
  const e = need(C(p.p), 'ex', '∃ 消去'), r = C(p.q, [...ctx, [p.h, sub(e.f, e.v, { v: p.x })]]);
  if (fv(r).has(p.x) || fv(e).has(p.x) || ctx.some(([, f]) => fv(f).has(p.x))) bad(`變數 ${p.x} 不夠新`);
  return r;
}
```

（`lean-prover/src/lean.js:101-106`）

`exI` 是「給出見證」：使用者必須提供一個具體的項 `p.t`，核心會檢查它確實滿足 `∃` 綁定的命題，否則就拒絕。`exE` 是「使用存在者」：從 `∃x. φ(x)` 得到 `φ(c)`，其中 `c` 是一個新變數，而且核心會強制檢查 `c` **夠新**——不能出現在結論、不能出現在被消去的公式、不能出現在上下文裡，否則拒絕。

於是兩邊的哲學清楚了：

| 面向 | ITP（`lean-prover`） | ATP（`theorem-prover`） |
|---|---|---|
| 量詞的命題 | 保留在目標與假設裡 | 全部消掉 |
| 存在者的處理 | 使用者給出**見證**（`exists t` 策略） | 機器**猜**一個 Skolem 項 |
| 綁定正確性的保證 | side condition：變數必須夠新 | 依賴清單：Skolem 項必須依賴所有外層全稱變數 |
| 失敗時的樣子 | 核心明確拒絕（「變數 x 不夠新」） | 默默產生一個可能錯的 Skolem 項，然後搜尋落空 |

兩邊都在處理同一個難題：**綁定變數的正確性**。ITP 把它變成一個可以被核心檢查的 side condition；ATP 把它變成一個**必須靠語意學保證**的靜默假設。

這裡有一個值得玩味的哲學差異。`exI` 讓「存在」成為一個**可被檢查的斷言**：你給出一個見證，核心確認它成立。而 Skolem 化讓「存在」成為一個**不可檢查的猜測**：機器選了 `sk1(x)`，這個猜測在某些模型裡對，在另一些模型裡錯。歸結法之所以還能運作，是因為它不需要猜對——它只需要一個矛盾，而矛盾會暴露猜測的錯誤。

用一句話總結這個反差：**ITP 把存在當成證明者提供的資訊，ATP 把存在當成證明者自己要去探索的東西。**

## 實作上的兩個小地方

第一，`skolem` 函式直接修改了全域的 `uid` 與 `skn` 計數器（第 45-46 行）。這代表 `clausify` **不是純函式**：同一個公式呼叫兩次，會得到不同名字的 Skolem 項。這對正確性沒有影響（名字只是標籤），但對「可重播性」有影響——第 4.5 節輸出的證明步驟鏈之所以能被重播，靠的是子句的**結構**而不是名字。

第二，`env` 是用物件展開 `{ ...env, [f.v]: ... }` 傳遞的，所以兄弟分支之間互不干擾；而 `us` 在 `and`/`or` 分支是**共用**的（同樣的 `us` 傳給左右兩邊）。這是正確的：左右兩支共用同一批外層全稱變數，因此兩邊的 `∃` 都依賴同樣的清單。

## 反事實推演：若不做 Skolem 化，Herbrand 定理會要求枚舉什麼？

第 2.4 節講過 Herbrand 定理：不可滿足性可以用有限的 ground instance 來證明。但那個定理有前提——你得先把公式裡的變數「具體化」成項，而 Herbrand 全域是這樣的：

$$
H = \{a, b, f(a), f(b), f(f(a)), \ldots\}
$$

對一個形如 $\exists x\, P(x)$ 的公式，Herbrand 式的做法是枚舉它在 $H$ 上的所有 ground instance：

$$
P(a),\quad P(b),\quad P(f(a)),\quad P(f(f(a))),\quad \ldots
$$

每一個都是一次**猜測**：我猜那個見證者就是這個項。

這裡有個麻煩：**項可以任意深地巢狀，所以猜測的空間是無界的**。要反駁 $\exists x\, P(x) \wedge \forall x\, \neg P(x)$ 這個公式，Herbrand 式的 prover 必須在無窮多個候選項裡猜中正確的那一個，而它無法事先知道要猜多深。

Skolem 化做的正是把這個無界的猜測**壓成一個有限的猜測**：引入一個全新的符號 `sk1`，把 $\exists x\, P(x)$ 換成 $P(sk1)$ 這樣的單一文字。見證者不再是從 Herbrand 全域裡挑一個既有項，而是「一個還沒被決定是什麼的新符號」。程式碼裡這就是那行 `{ f: 'sk' + (++skn), a: us }`（第 63 行）——`sk1` 是一個**零元函數符號**，相當於一個新鮮的常數。實測：

```
$ node bin/cli.js -e "exists x. P(x)" "forall x. ~P(x)"
✔ 前提互相矛盾(產生 3 個子句,0 ms)
  1. P(sk1)    [前提]
  2. ~P(X2)    [前提]
  3. ⊥    [歸結 2, 1]
```

（毫秒數隨機器而異。）三個子句就結束了。沒有任何一個 Herbrand 項被枚舉出來——`sk1` 是被**引進**的，不是被**猜中**的。這也回答了 Skolem 化為什麼值得那個代價：**它把「猜哪一個項」換成「猜一個新符號的形狀」**，而形狀只由 $\exists$ 的數目與量化深度決定，選項有限。

## `++skn` 為什麼必須是全域計數器

`skn` 是全域變數（第 45 行），每呼叫一次 `skolem` 就遞增，所以**同一個問題裡不同的 $\exists$ 會得到不同的 Skolem 符號**。這不是命名上的潔癖，而是正確性的必要條件。

取一個可滿足、但看起來很危險的例子：

```
$ node bin/cli.js -e "forall x. exists y. P(x,y)" "forall x. exists y. ~P(x,y)"
✘ 無法證明:子句集已飽和,結論不是前提的邏輯後果
```

這兩個公式其實可以同時成立：取 $P(x, y)$ 為「不相等」這個關係（論域至少有兩個元素），則對每個 $x$ 而言，既有不等於它的 $y$ 可選，也有恰好等於它的 $y$ 可選。所以 prover 回報飽和是**正確的**。

現在做一個反事實實驗：把 `clausify` 改成在每次呼叫前把 `skn` 重設為 0（等於兩個公式共用同一組 Skolem 符號），再跑一次同一組前提：

```
✔ 前提互相矛盾(產生 3 個子句,3 ms)
  1. P(X2,sk1(X2))    [前提]
  2. ~P(X4,sk1(X4))    [前提]
  3. ⊥    [歸結 2, 1]
```

（毫秒數隨機器而異。）兩個子句現在**形狀相同**，於是歸結立刻得到 `⊥`——一個**假的矛盾**。這個假矛盾正是兩個不同的 $\exists$ 被當成同一個 $\exists$ 而造成的。本節開頭說 Skolem 化是第一個不可逆的步驟、程式碼開始「猜」；這個實驗說明那個猜測一旦猜錯，整個證明器就會自信地證明一件不成立的事。**可滿足性檢查器最危險的失效模式不是漏報，而是誤報。**

## 從模型論問題到合一代數問題

Skolem 化最深的後果不在子句集，而在**問題的種類**。

原來的問題是模型論的：「是否存在一個模型同時滿足這組公式？」要回答它，需要理解「項」與「模型」。Skolem 化之後，問題變成合一代數的：「這個子句和那個子句的引數能不能對上？」要回答它，只需要第 4.4 節那個 `unify()`。

具體說，Skolem 化替我們卸下三樣模型論的負擔：

- **見證者的選出不再是前提的一部分。** Skolem 化之前，反駁 $\exists x\, P(x)$ 要求 prover 端出一個具體的項；之後，它只要端出一個符號。
- **量詞的束縛正確性從「需要檢查」變成「需要保證」。** 依賴清單 `us` 取代了 ITP 裡的 side condition；只要 `us` 記全了，Skolem 定理就保證「Skolem 形式可滿足 ⟺ 原公式可滿足」。
- **自由變數不再代表「對所有」。** 子句裡的變數隱含全稱，所以 `case 'all'` 的替換（第 62 行）在語意上是中立的。

於是「存在」在本實作裡變成一個**由語意學保證兜底的可檢查物件**。這正是第 4.1 節對照表裡「綁定正確性的保證」那一列的具體內容：ATP 用語意學保證，ITP 用核心檢查。

## 下一節

Skolem 化之後，子句裡只剩下：謂詞名、參數、變數，以及等式。而接下來要解決的問題是——**兩個變數怎麼知道它們是「同一個東西」**？

第 4.4 節要處理合一（unification）與匹配（matching）：歸結法怎麼把 `~Man(X2) | Mortal(X2)` 和 `~Mortal(socrates)` 這兩個看起來毫不相干的子句接上。那裡會出現一個看起來多餘、但絕對不能刪的檢查——occurs check。
