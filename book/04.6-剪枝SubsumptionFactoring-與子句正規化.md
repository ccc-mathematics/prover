# 4.6 剪枝：Subsumption、Factoring 與子句正規化

第 4.5 節的迴圈跑得通，但它是靠蠻力撐起來的。每一輪都會產生一批新子句，而新子句又會在未來的每一輪裡被拿來跟別的子句做運算。如果沒有任何機制清理冗餘，子句數會以組合級的速度膨脹，搜尋空間隨之爆炸。

本節要拆三個機制。它們在本實作裡各佔一小段程式碼，但每一段都對應一個真實的理論技術：

| 機制 | 函式 | 位置 | 作用 |
|---|---|---|---|
| 正規化 | `norm()` | `:114-120` | 丟掉恆真子句、合併重複文字、統一變數名 |
| 包含剪枝 | `subsumes()` / `prune()` | `:104-112` / `:146` | 用更強的子句淘汰較弱的 |
| 因子化 | 迴圈內的 factor 區塊 | `:166-170` | 把兩個可合一的同號文字合併成一個 |

## norm()：先把自己整理乾淨

```js
function norm(lits) { // 去重複文字、剔除恆真子句、變數改名
  const seen = new Set(), out = [];
  for (const l of lits) { const k = ls(l); if (!seen.has(k)) { seen.add(k); out.push(l); } }
  if (out.some(l => l.s && l.n === '=' && ts(l.a[0]) === ts(l.a[1]))) return null; // t = t 恆真
  for (const l of out) if (seen.has(ls({ ...l, s: !l.s }))) return null;
  return ren(out);
}
```

（`theorem-prover/src/prover.js:114-120`）

四個步驟，每一步都有存在的理由。

**去重複文字。** 用 `ls(l)`（文字的字串表示，第 96 行）當鍵，把重複的文字丟掉。`P(a) | P(a)` 變成 `P(a)`。這不只是美觀：文字越少，子句越短，權重越小，越容易在後續的搜尋裡被優先挑選，也越不容易被別的子句包含。

**剔除恆真的等式。** `t = t` 是一個恆真的文字（例如 `f(x) = f(x)`），任何模型都滿足它。只要子句裡有這種文字，整個子句就是恆真的——對矛盾毫無貢獻。所以這種子句被整個丟棄（`return null`）。

**剔除重言式子句。** 第三行檢查子句裡是否同時出現 `P` 與 `¬P`。若是，則 `P ∨ ¬P` 恆真，整個子句同樣無用。這一步用了一個小技巧：把文字的正負號翻轉（`{ ...l, s: !l.s }`）後再看它是否在 `seen` 裡。由於 `ls` 對等式的正負號分別印成 ` = ` 與 ` != `（第 96 行），等式文字的重言式檢查也被同一段程式碼免費處理了。

**變數改名。** 最後 `ren(out)` 把子句裡的每個變數換成全新的名字。這一步有兩個作用：一是讓 `subsumes` 與 `accept` 的比較永遠在「不同變數名」的兩個子句之間進行，避免同一個變數名在兩個子句裡被誤認為是同一個（這正是第 4.4 節談過的捕獲問題）；二是讓輸出裡的變數編號一路遞增，成為每個子句的指紋。

回傳 `null` 代表「這個子句沒有價值，丟掉」。`accept()` 看到 `null` 就直接 `return null`，子句不會進入子句集。

## subsumes()：誰比誰強

```js
function subsumes(c, d, s = {}, i = 0) { // c 是否包含 d
  if (i === c.length) return true;
  for (const l of d) {
    if (l.s !== c[i].s || l.n !== c[i].n || l.a.length !== c[i].a.length) continue;
    let t = s; for (let j = 0; j < l.a.length && t; j++) t = match(c[i].a[j], l.a[j], t);
    if (t && subsumes(c, d, t, i + 1)) return true;
  }
  return false;
}
```

（`theorem-prover/src/prover.js:104-112`）

這是一個雙重迴圈的指派問題：把 `c` 的每一個文字，依序指派到 `d` 的某個文字上（`c[i]` 對 `d` 的某個 `l`），而且指派必須滿足：正負號相同、謂詞名相同、元數相同，且引數之間**單向匹配**（用第 4.4 節的 `match`）。每個 `c` 的文字都要有著落，才算 `c` 包含 `d`。

「包含」在語意上的意思正是：**`c` 的每個實例都是 `d` 的實例**，也就是 `c` 比 `d` 強。若 `c` 的某個實例滿足了 `c`，那它必然也滿足 `d`，所以 `d` 是多餘的。

方向性由 `match` 的單向性決定，實測幾組：

- `subsumes(P(X), P(a))` 為真——`∀x P(x)` 蘊含 `P(a)`，變數版本更一般。
- `subsumes(P(a), P(X))` 為假——常數版本不能蘊含全稱版本。
- `subsumes(P(X), P(Y))` 為真——兩個全稱版本互相蘊含。
- `subsumes(P(a) & Q(b), P(a) & Q(c))` 為假——`b` 與 `c` 是不同的常數，匹配失敗。

這正是第 4.4 節強調 `match` 必須是**單向**的原因。如果 `match` 可以反向綁定變數，這個判斷的方向就會翻轉，剪枝會變成丟掉強的、留下弱的。

## prune()：新子句淘汰舊子句

有了 `subsumes`，剪枝就是兩行：

```js
const prune = (arr, c) => { for (let i = arr.length; i--; ) if (arr[i].lits.length >= c.lits.length && subsumes(c.lits, arr[i].lits)) arr.splice(i, 1); };
```

（`theorem-prover/src/prover.js:146`）條件是「`arr[i]` 的文字數不少於 `c`，而 `c` 包含 `arr[i]`」。文字數的比較是快速篩選：更強的子句必然不會有更多文字。

`accept()` 裡還有一道反向的檢查：

```js
for (const c of active.concat(passive)) if (c.lits.length <= l.length && subsumes(c.lits, l)) return null;
```

（`theorem-prover/src/prover.js:149`）這是「新子句被既有子句包含」的檢查。兩道檢查合起來構成完整的冗餘判定：

- 新子句比舊的弱 → 丟掉新子句（上面這行）。
- 新子句比舊的強 → 丟掉舊子句（`prune`）。

**這是 ATP 從玩具變成可用的分水嶺。** 沒有剪枝時，每一輪新產生的子句都會永久留在集合裡並被反覆拿來配對，子句數隨著深度指數成長；有了剪枝，集合裡只留下互不包含的「極小」子句，數量從指數降到多項式。現代 ATP 的效率幾乎全部建立在這類冗餘消除之上。

有一個實作上的細節值得一提：`prune` 只從 `active` 與 `passive` 裡移除子句，**不碰 `all`**。所以被淘汰的子句仍然留在記錄簿裡，第 4.5 節說過的證明鏈重建因此不受影響——剪枝不會破壞已經找到的證明。

## factoring：為什麼必須有這一條

第三個機制因子化，在迴圈裡的這段：

```js
for (let i = 0; i < g.lits.length; i++) for (let j = i + 1; j < g.lits.length; j++) { // 因子化
  if (g.lits[i].s !== g.lits[j].s) continue;
  const s = unifyL(g.lits[i], g.lits[j], {});
  if (s) news.push([g.lits.filter((_, k) => k !== j).map(x => applyL(x, s)), 'factor', [g.id]]);
}
```

（`theorem-prover/src/prover.js:166-170`）它找子句裡**兩個同號**的文字，若它們能合一，就把它們合併：刪掉第二個文字，把合一結果套回第一個。

為什麼需要它？先看它在語意上做了什麼。子句 `P(x) ∨ P(y)` 裡的 `x`、`y` 都是全稱變數，所以整個子句等價於單位子句 `P(x)`——因為 `∀x∀y (P(x) ∨ P(y))` 與 `∀x P(x)` 等價。但**歸結永遠無法從 `P(x) ∨ P(y)` 產生 `P(x)`**：歸結規則要求兩個文字正負相反（第 180 行的 `if (a.s === b.s) continue;`），而這裡的兩個文字都是正號，沒有機會相消。因子化正是填補這個缺口：它把兩個同號文字**合併**成一個，讓單位子句浮出水面。

最漂亮的證明是 `examples/barber.txt`。它的輸出是：

```
✔ 前提互相矛盾(產生 5 個子句,2 ms)
  1. ~Shaves(sk1,X2) | ~Shaves(X2,X2)    [前提]
  2. Shaves(X3,X3) | Shaves(sk1,X3)    [前提]
  3. Shaves(sk1,sk1)    [因子化 2]
  4. ~Shaves(sk1,sk1)    [因子化 1]
  5. ⊥    [歸結 4, 3]
```

理髮師悖論的結構是「理髮師給自己理髮當且僅當他不給自己理髮」。子句化之後得到兩條子句。因子化第 2 條：`Shaves(X3,X3)` 與 `Shaves(sk1,X3)` 的引數可合一（`X3 ↦ sk1`），合併後得到 `Shaves(sk1,sk1)`——正是「理髮師給自己理髮」。因子化第 1 條同理得到 `~Shaves(sk1,sk1)`。兩條單位子句一正一負，歸結立刻得到空子句。

**如果把因子化這段程式碼刪掉，理髮師悖論就證不出來了。** 用一份去掉因子化的副本能實測：狀態從 `proved` 變成 `saturated`（只產生 2 個子句就停）。這是本實作裡因子化必要性的最硬證據。原因是：第 1、2 條子句之間的歸結嘗試都會失敗——`~Shaves(sk1,X2)` 與 `Shaves(X3,X3)` 歸結時，`X3` 同時要被綁成 `sk1` 又要被綁成 `X2`，衝突；另一個方向則產生 `~Shaves(sk1,sk1) | Shaves(sk1,sk1)` 這個重言式，被 `norm()` 丟掉。**因子化是把這個悖論推下懸崖的最後一腳。**

順帶說明一個陷阱。因子化是「**合併**」，不是「**互相抵消**」。如果把它誤寫成「兩個可合一的同號文字互相刪除」，那麼 `P(x) ∨ P(y)` 在合一 `x ↦ y` 之後就會變成空子句——而這個空子句並不被任何模型所蘊含，會產生一個**假矛盾**。本實作的寫法只刪掉第二個文字（`filter((_, k) => k !== j)`）、保留合併後的第一個，所以結構上就排除了這個錯誤。歸結規則裡「正負相反才准相消」的硬性要求（第 180 行）同樣是這道護欄。

## 這個實作還缺什麼

把三個機制放在一起看，本實作已經有了一個「能用的」歸結器：它能證明假言三段論、Peirce 定律、傳遞性、等式代入，甚至群論裡「單位元的反元素是單位元」這條需要巧思的命題（第 4.7 節會詳細走一遍）。

但與現代 ATP 比起來，缺了五樣東西，而它們正是第 8 章的主題：

| 缺的技術 | 作用 | 現代替代品 |
|---|---|---|
| **單位傳播**（unit propagation） | 把單位子句立刻套用到所有子句上 | 只有「權重小優先」的粗略啟發式 |
| **純文字刪除**（pure literal elimination） | 若某謂詞只以正號出現，可刪掉負號文字 | 完全沒有 |
| **支撐集限制**（set of support） | 限制新子句必須包含否定結論的祖先 | 完全沒有，搜尋空間是全開的 |
| **選擇引理**（selecting lemmas） | 限制父句中可用哪些文字 | 完全沒有 |
| **項排序與化簡**（term ordering & simplification） | 限制等式替換的方向、消掉冗餘等式 | 完全沒有，第 4.7 節的主題 |

其中「支撐集限制」的影響最直接。現代 ATP 在歸結時只考慮那些「從否定結論一路推導上來」的子句所參與的歸結，這能把搜尋空間縮小數個數量級。本實作則是把所有前提子句都放進同一個池子裡平等對待——簡單，但浪費。

第 4.5 節提過權重啟發式「近似單位子句優先」。現在可以說得更精確：**真正的單位傳播是一個推理規則**（把單位子句與每個子句歸結，結果立刻放進集合），而權重啟發式只是一個**排序偏好**（優先挑看起來短的子句來處理）。前者能保證「短子句的影響立刻擴散到整個集合」，後者只能保證「短子句先被處理」。兩者的差距，就是玩具與工具的差距。

## 反事實實測：把剪枝拿掉會怎樣

第 4.5 節說過剪枝「把子句數從指數降到多項式」。這句話很容易滑過，但它其實是本實作能不能用的分界線。把 `accept()` 裡的包含檢查刪掉、把 `prune(active, c); prune(passive, c);` 這兩個呼叫拿掉，跑一遍內建的九個範例，得到：

| 範例 | 有剪枝 | 無剪枝 |
|---|---|---|
| 蘇格拉底三段論 | `proved`，6 個子句 | `proved`，6 個子句 |
| 理髮師悖論 | `proved`，5 個子句 | `proved`，9 個子句 |
| Peirce 定律 | `proved`，3 個子句 | `proved`，4 個子句 |
| 飲酒者悖論 | `proved`，3 個子句 | `proved`，3 個子句 |
| 傳遞關係 | `proved`，30 個子句 | `proved`，49 個子句 |
| 等式代入 | `proved`，9 個子句 | `timeout`，20001 個子句 |
| f(f(a)) = a 的推論 | `proved`，17 個子句 | `proved`，20 個子句 |
| 群論：單位元的反元素 | `proved`，71 個子句 | `timeout`，20001 個子句 |
| 非定理（應回報失敗） | `saturated`，2 個子句 | `saturated`，2 個子句 |

（`timeout` 那一欄撞的是預設上限，第 144 行的 10 秒 / 20000 個子句。）

前面幾列的差別只是常數倍，後兩列卻是**性質上的差別**：「等式代入」原本 9 個子句就能證完，關掉剪枝之後兩萬個子句都還沒找到矛盾，只能回報「結果未知」；群論範例更明顯——第 4.7 節講過它有剪枝時產生 71 個子句就收工，沒有剪枝時同樣兩萬個子句不夠。

這個對照說明：**剪枝不是最佳化，而是可行性條件**。第 4.5 節講過權重啟發式「近似單位子句優先」，而剪枝才是讓這個啟發式有東西可選的前提——如果集合裡塞滿互不包含的等價物，再怎麼挑短子句都只是在雜訊裡打轉。

（實測方式：把 `theorem-prover/src/prover.js` 複製一份，在副本上刪掉上述兩處，再用 `node -e` 遍歷 `require('./src/prover.js').examples`，比較兩個版本 `prove()` 回傳的 `status` 與 `generated`。）

## subsumption 的兩道牆

`subsumes()` 是一個漂亮但保守的判斷。它只看文字的形狀與引數的**單向匹配**，於是有兩類冗餘它認不出來。

第一類是**需要等式資訊才能看出的冗餘**。`subsumes` 完全不碰等式公理：假設集合裡有 `f(a) = b`，新子句是 `P(f(a))`。在有等式的世界裡，`P(f(a))` 已被 `f(a) = b` 蘊含，語意上多餘；但 `subsumes(P(b), P(f(a)))` 與反方向都為假——`match` 要求兩邊的函數符號逐字相同，`b` 對不上 `f(a)`。本實作沒有項排序與化簡（第 4.7 節的主題），這類冗餘只能靠等式替換產生的新子句去撞，撞不到就留在集合裡。

第二類是**需要「單位傳播」才看得出的冗餘**。第 4.5 節提過真正的單位傳播是一條推理規則而非排序偏好；本實作沒有它，所以單位子句的效力不會立刻擴散到整個集合，只能等它被挑出來之後主動跟別的子句歸結。

還有一個成本面的牆：`accept()` 裡的包含檢查是

```js
for (const c of active.concat(passive)) if (c.lits.length <= l.length && subsumes(c.lits, l)) return null;
```

（`theorem-prover/src/prover.js:149`）也就是**每個新子句都要跟集合裡的每一個子句比一次**，而 `subsumes` 本身是個指派問題，最壞情況是階乘。第 4.5 節說過權重挑選用的是線性掃描、「在子句數上千時會成為熱點」；這一行的 `active.concat(passive)` 每輪都重新配置一個陣列，是同一類熱點。現代 ATP 用「特徵索引」（依謂詞名與 arity 分桶）避免做這麼多次全比，本實作沒有。

## 三道防線的分工

把本節的三個機制擺在一起看，它們各自砍掉的是不同種類的浪費：

- `norm()` 砍掉**子句內部**的冗餘：重複文字、恆真等式 `t = t`、重言式 `P ∨ ¬P`，並把變數改名，讓後續比較永遠發生在「不同變數名」之間。
- `subsumes()` 與 `prune()` 砍掉**子句之間**的冗餘：同一個事實的弱版本，無論是既有的還是新產生的。
- `factor()` 補上**推理規則層面**的漏洞：`P(x) ∨ P(y)` 這類子句裡的同號文字無法互相抵消，必須靠因子化合併，歸結才有機會用上它。

三者的順序不是任意的：`norm()` 必須先跑，因為 `subsumes` 的比對結果依賴文字的規範形狀；而 `prune` 又必須在 `passive.push(c)` 之前跑，因為一旦新子句進了佇列，它就已經可以被挑出來當 given clause 了。

## 下一節

前三個機制都只處理「文字與文字」的關係。本節的剪枝、上一節的因子化、還有第 4.5 節的核心歸結規則，全部都在同一個抽象層級上運作：文字是原子，文字之間要嘛同號要嘛異號。

但有一類公式的推理根本不是靠「文字相消」完成的——**代數**。要證明 `mul(inv(e), e) = e`，需要的是「把 `mul(inv(e), e)` 這個項**換成**另一個項」，而不是把兩個文字刪掉。第 4.7 節要處理的就是這條線：參數替換（paramodulation）與等式歸結（equality resolution），以及它們如何讓這個 225 行的程式在等式密集的題目上展現出與 ITP 不同的能力。
