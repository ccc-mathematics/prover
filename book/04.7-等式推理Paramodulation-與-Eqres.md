# 4.7 等式推理：Paramodulation 與 Eqres

前六節的推理規則都在做同一件事：**把文字兩兩配對、互相抵消**。`~Man(X2)` 對上 `Man(socrates)`，消去，得到 `~Man(socrates)`。這種操作的前提是文字是原子的——它們要嘛是 `P(t1, ..., tn)`，要嘛是 `¬P(t1, ..., tn)`，沒有內部結構。

但等式不是這樣的。`mul(e, x) = x` 這個式子裡有**結構**：`mul` 是一個函數，`e` 與 `x` 是它的引數。要從它推出別的東西，必須能說「把某個地方出現的 `mul(e, x)` 換成 `x`」——這是**改寫**，不是抵消。本節要處理的就是這條規則族：參數替換（paramodulation）與等式歸結（equality resolution）。

## 為什麼一階邏輯需要等式

先問一個基本的問題：沒有等式，一階邏輯會少掉什麼？

答案是：整個代數。沒有等式時，`mul(e, x) = x` 只不過是一個有兩個參數的謂詞——`mul` 與 `e` 都只是名字，邏輯上與任何別的謂詞沒有分別。「`e` 是單位元」這件事將無法表達，因為語言裡沒有任何東西說 `e` 和 `mul` 之間有關係。

等式帶來的是**可替換性**（Leibniz 定律）：如果 `t = s`，那麼任何公式裡的 `t` 都可以換成 `s` 而不改變真假。這個性質正是「代數推理」的形式化——我們之所以能說「把 `mul(inv(x), x)` 換成 `e`」，就是因為等式告訴我們 `mul(inv(x), x) = e` 恆成立。

在邏輯學的歷史裡，這是等式邏輯（equality logic）與無等式一階邏輯的分野。Robinson 1965 年那篇奠基論文的標題裡，「resolution with equality」就是要把等式納入歸結框架。本實作是同樣的企圖，只是用最直觀的方式完成。

## pos()：列舉一個項的所有子項

替換的第一步是「找出項裡可以動手的地方」。`pos()` 是一個生成器（generator），它遞迴走過一個項的所有子項位置：

```js
function* pos(t) {
  if (isV(t)) return;
  yield [t, x => x];
  for (let i = 0; i < t.a.length; i++) for (const [u, k] of pos(t.a[i])) yield [u, x => ({ f: t.f, a: t.a.map((y, j) => j === i ? k(x) : y) })];
}
```

（`theorem-prover/src/prover.js:123-127`）

每次 yield 的是一對東西：**子項 `u`** 與**重建函數 `k`**。`k` 的作用是「把這個子項換成某個新項之後，把整個項重建回來」。例如對項 `f(g(a), b)`，位置 `g(a)` 的重建函數是「把第一個引數換掉」：

$$
k(x) = f(x, b)
$$

有了 `k`，替換就變成一句話：「把引數位置 `i` 換成 `k(r)`」。

兩個細節值得留意。第一，變數**不會被 yield**（`if (isV(t)) return;`）——變數本身沒有內部結構可改寫。第二，yield 順序是先整個項、再往引數深處走，所以最外層的替換機會先被嘗試。

## para()：參數替換

```js
function para(A, B, ida, idb, out) {
  for (const e of A) {
    if (!e.s || e.n !== '=') continue;
    for (const [l, r] of [[e.a[0], e.a[1]], [e.a[1], e.a[0]]]) {
      if (isV(l)) continue;
      for (const L of B) for (let i = 0; i < L.a.length; i++) for (const [u, k] of pos(L.a[i])) {
        const s = unify(l, u, {}); if (!s) continue;
        const L2 = { s: L.s, n: L.n, a: L.a.map((y, j) => j === i ? k(r) : y) };
        out.push([[...A.filter(x => x !== e), ...B.map(x => x === L ? L2 : x)].map(x => applyL(x, s)), 'para', [ida, idb]]);
      }
    }
  }
}
```

（`theorem-prover/src/prover.js:128-140`）

規則的形式是：從子句 `A` 裡的一條正等式 `l = r`，與子句 `B` 裡某個含子項 `u` 的文字，推出把 `u` 換成 `r` 的新子句。

四層迴圈，分別對應四個「選擇」：

1. **挑 `A` 裡的一條等式**（只取正號的 `=` 文字）。
2. **挑方向**：`l → r` 與 `r → l` 兩個方向都試。等式是對稱的，所以兩個方向都是合法的改寫；只試一個方向會漏掉一半的推論。
3. **挑 `B` 裡的文字與引數位置**：`for (const L of B) for (let i = 0; i < L.a.length; i++)`。注意是「文字的引數」，不是「整個文字」——`P(f(a))` 裡的 `f(a)` 是 `P` 的第一個引數。
4. **挑子項**：用 `pos()` 列舉出該位置的所有子項 `u`，然後 `unify(l, u, {})` 檢查等式的左邊能不能與這個子項對上。

替換本身是第 135 行：

```js
const L2 = { s: L.s, n: L.n, a: L.a.map((y, j) => j === i ? k(r) : y) };
```

把第 `i` 個引數換成 `k(r)`——也就是「用重建函數把新項塞回原位」。然後第 136 行組出結果子句：

```js
out.push([[...A.filter(x => x !== e), ...B.map(x => x === L ? L2 : x)].map(x => applyL(x, s)), 'para', [ida, idb]]);
```

三件事：把 `A` 裡那條被用掉的等式**移除**；把 `B` 裡被改寫的文字換成 `L2`；最後把合一結果 `s` 套用到整個子句。

兩個設計決定值得挑明。

**`if (isV(l)) continue;`——等式的左邊不能是變數。** 因為 `x = y` 這樣的等式是「兩個變數等價」，把變數整個換掉會破壞量化結構。標準的參數替換規則也要求替換的左邊不是變數。

**等式被丟掉。** 這是本實作與教科書寫法的最大差別。標準規則的結論是 $\{l = r\} \cup C \cup D[r]$ 這個形狀：等式**保留**在結果裡。本實作把它刪了。這個取捨有清楚的取捨理由：刪掉之後，結論變成「`B` 中那個文字的一個實例」，所以**可靠性不受影響**（前提仍然蘊含結論）；但**完備性打折**——等式從此離開子句集，不能再被拿來做別的替換。現代 ATP 用「超對稱」（superposition）取代這條規則，並且靠項排序保證等式既被保留又被正確簡化。

## eqres：等式歸結

第二條規則處理不等式：

```js
for (const l of g.lits) { // 等式歸結:消去 t != t'
  if (l.s || l.n !== '=') continue;
  const s = unify(l.a[0], l.a[1], {});
  if (s) news.push([g.lits.filter(x => x !== l).map(x => applyL(x, s)), 'eqres', [g.id]]);
}
```

（`theorem-prover/src/prover.js:171-175`）

規則是：看到否定等式 `t != t'` 時，若兩端能合一，就表示 `t` 與 `t'` 其實是同一個東西，於是 `t != t` 是矛盾，這條文字直接被刪掉。

為什麼需要它？因為第 4.1 節說過，反駁法的目標是「把否定結論塞進子句集，找到矛盾」。若否定結論裡有不等式（`inv(e) != e`），光靠一般的歸結是找不到矛盾的——必須有一條規則專門處理「不等式兩端其實相同」的情形。`eqres` 就是那條規則。

它的實作只有三行，因為邏輯非常簡單：檢查正負號與謂詞名、合一兩端、成功的話把這個文字刪掉。注意刪掉之後，剩下的文字還要套用合一結果 `s`（因為合一可能改變了其他文字裡的變數）。

## 走一遍群論範例

`examples/group.txt` 是這個實作最能說明問題的案例：

```
forall x. mul(e,x) = x
forall x. mul(inv(x),x) = e
forall x y z. mul(mul(x,y),z) = mul(x,mul(y,z))
|- inv(e) = e
```

要證的是「單位元的反元素就是單位元」。子句化之後（量詞變成自由變數）：

```
1. mul(e,X2) = X2              [前提]        左單位律
2. mul(inv(X4),X4) = e          [前提]        反元素的定義
3. mul(mul(X8,X9),X10) = mul(X8,mul(X9,X10))   [前提]   結合律
4. inv(e) != e                  [否定結論]
```

前三條是群論的公理化表述，第四條是「假設結論不成立」。整個證明的任務就是：從公理推出 `inv(e) = e`，然後與第四條相撞。

實際的輸出（中間省略大量被剪枝掉的子句）：

```
  1. mul(e,X2) = X2    [前提]
  2. mul(inv(X4),X4) = e    [前提]
  3. mul(mul(X8,X9),X10) = mul(X8,mul(X9,X10))    [前提]
  4. inv(e) != e    [否定結論]
  7. mul(mul(inv(X15),X15),X16) = X16    [等式替換 2, 1]
 13. mul(mul(X91,e),X92) = mul(X91,X92)    [等式替換 1, 3]
 19. mul(inv(X105),mul(X105,X106)) = X106    [等式替換 3, 7]
 501. mul(mul(inv(X1856),e),X1856) = e    [等式替換 13, 2]
 1234. mul(inv(inv(X4612)),e) = X4612    [等式替換 2, 19]
 1266. mul(X4724,inv(X4724)) = e    [等式替換 1234, 501]
 1274. e = inv(e)    [等式替換 1266, 1]
 1474. e != e    [等式替換 1274, 4]
 1537. ⊥    [等式歸結 1474]
```

逐步看每一步的**數學內容**：

**第 7 步**用第 2 條（`mul(inv(x),x) = e`）去改寫第 1 條裡的常數 `e`。把 `e` 換成 `mul(inv(a),a)`，得到 `mul(mul(inv(a),a),x) = x`。意思是：**任何元素的反元素自乘，也扮演左單位元的角色**。

**第 13 步**用左單位律 `mul(e,·) = ·` 去改寫結合律右邊的 `mul(X9,X10)`（它形如 `mul(·,·)`，可被 `mul(e,_2)` 匹配），把它換成 `X10`，同時合一把 `X9` 綁成 `e`，於是得到 `mul(mul(x,e),z) = mul(x,z)`——**右單位律**。這正是群論裡「由結合律與左單位律推出右單位律」的那個標準推論，只不過在這裡是被機器自動做出來的。

**第 19 步**用結合律把 `mul(mul(inv(a),a),x)` 展開成 `mul(inv(a),mul(a,x))`，得到 `mul(inv(a),mul(a,x)) = x`。

**第 501 步**用剛得到的右單位律去改寫第 2 條裡的 `mul(inv(a),a)`，把它變成 `mul(mul(inv(a),e),a) = e`。

**第 1234 步**用第 2 條把第 19 步裡的 `mul(a,x)` 換成 `e`，得到 `mul(inv(inv(b)),e) = b`。

**第 1266 步**結合第 1234 步與第 501 步，得到 `mul(a,inv(a)) = e`——**左反元素原來也是右反元素**。

**第 1274 步**是最後一塊拼圖：把 `mul(e,x) = x`（左單位律）與 `mul(a,inv(a)) = e` 結合，令 `a = e`，得到 `mul(e,inv(e)) = e`；而左單位律又說 `mul(e,inv(e)) = inv(e)`；兩者一比就是 **`e = inv(e)`**。

**第 1474 步**把 `e = inv(e)` 代入否定結論 `inv(e) != e`，得到 `e != e`。

**第 1537 步**由 `eqres` 收尾：`unify(e, e)` 成功，`e != e` 是矛盾，該文字被刪掉，子句變空，證明完成。

整條鏈產生 1537 個子句，耗時數百毫秒。**注意「1537」這個數字**：它在說明這條路的代價。機器在沒有人指路的情況下，靠幾千次盲目的改寫與取消，把「單位元的反元素是單位元」這個需要人想上三十秒的命題推出來了。

## 為什麼這是 ATP 的強項

第 3 章講過 ITP 在等式上的窘境：`lean-prover` 的自然演繹裡，「`mul(inv(e),e) = e`」必須由人寫成一串 `have` 與 `exact`，而且每一步都要對 `mul` 的引數結構有正確的認識。策略寫錯，核心就會回報「核心檢查失敗」，但它不會自己去試「用結合律把 `mul(mul(x,y),z)` 改寫成 `mul(x,mul(y,z))`」。

歸結法不需要這種洞見。它只是窮舉所有可能的改寫，把「結合律」與「左單位律」與「反元素定義」當成可以互相代入的磚頭，任憑它們互相碰撞。**在等式密集的題目上，這種「多試幾種可能」的方法恰好非常有效**，因為代數推論的本質就是「把等式到處代入」。

代價則是那 1537 個子句：每一次改寫都朝兩個方向嘗試，每一次改寫都產生一個新的變數版本，數量爆炸。第 6.7 節會把同一批命題放進三個系統裡各跑一遍，把這個對比量化。

## 限制：為什麼它還是會逾時

README 的「限制」段落說得很直接：

> 等式推論沒有項排序與化簡，較難的代數題可能逾時；預設上限為 10 秒、20000 個子句。

這句話背後是三個具體的缺失。

**沒有項排序。** 現代 ATP 會給所有項一個排序（例如以「項的深度、然後字典序」為準），並且**只允許從大到小**的替換（把較大的項換成較小的項）。這保證了替換是「簡化」而不是「膨脹」，也让推理在有限時間內收斂。本實作兩個方向都試（第 131 行），於是 `e` 與 `mul(inv(a),a)` 可以互相替換，產生了大量等價的變體——第 7 步與第 1274 步其實是同一個想法的兩面。

**沒有化簡。** 現代 ATP 會在產生新子句後立刻做「化簡」：把 `mul(e, x)` 化簡成 `x`（用左單位律），把 `mul(x, x)` 裡的相同引數合併。本實作不做化簡，所以 `mul(mul(inv(X1856),e),X1856)` 這種明顯可以化簡的項會一直留在子句集裡，被反覆拿來配對。

**等式在替換後被丟掉。** 前面說過，這讓推論系統在等式部分不再完備：本來可以拿來做下一次替換的等式，就這樣消失了。

再加上第 4.6 節列出的「沒有單位傳播、沒有支撐集限制」，複雜的代數題會在十秒內生出一萬幾千個子句然後逾時。逾時的輸出是：

```
… 超過時間或子句數上限,結果未知
```

注意「結果未知」四個字。**「我沒找到」不等於「不存在」**——這是第 4.1 節講過的 ATP 的先天缺陷，在等式題目上表現得最明顯：越是需要巧思的等式推論，搜尋越容易在雜訊裡迷路。

## 本章結語：從「驗證」到「搜尋」，再到「型別」

本章把 ATP 的三根支柱逐一拆開：子句化（第 4.2、4.3 節）、合一（第 4.4 節）、搜尋（第 4.5 節），再加上讓它真正能用的兩個附件——剪枝（第 4.6 節）與等式（第 4.7 節）。

回頭看第 4.1 節那張對照表，現在可以填上更精確的內容。ATP 與 ITP 的分工，不只是「誰負責想」，更是**三種不同的信任結構**：

| | ITP（`lean-prover`） | ATP（`theorem-prover`） | λ-Cube（`lambda-cube`） |
|---|---|---|---|
| 信任什麼 | 核心 `check()` 的判定 | 推論規則的可靠性 | 型別判定的可靠性 |
| 人給什麼 | 證明項 | 前提與結論 | 型別註記與項 |
| 失敗長什麼樣 | 明確拒絕 | 語意空洞 | 型別錯誤訊息 |
| 證明的對象 | 證明項本身 | 一條矛盾鏈 | 型別本身 |

三個系統都遵守第 7 章將要談的 De Bruijn 準則：**把信任集中在最小的核心裡**。只是它們對「最小」的定義不同——ITP 的核心是一個只讀證明項的檢查器，ATP 的核心是一組只做子句運算的規則，λ-Cube 的核心是一個只做型別推導的函式。

而 ATP 與另外兩者的分野最深的地方，在於它多了一項 ITP 與型別檢查器都不需要的東西：**一個不保證找得到答案的搜尋程序**。ITP 與 λ-Cube 都是「給我一個證明，我檢查它」；ATP 是「給我一個問題，我去找證明，找不到就說不知道」。這個差別不是工程細節，而是邏輯學裡「證明論」與「模型論」的分野——第 6 章會把這條線拉到最長。

第 5 章要轉向第三個系統。λ-Cube 做的事情與前兩個都不同：它不驗證證明項，也不搜尋矛盾，而是**把命題邏輯整個重新編碼成型別系統**。Curry–Howard 對應會告訴我們：一個命題就是一個型別，一個證明就是一個符合該型別的項。於是「證明」這件事，變成了一件可以交給型別推導引擎的、純粹機械的工作。

從 ITP 到 ATP，再到 λ-Cube，三個系統各自回答了「機器如何對付證明」的一個面向。第 5 章會讓我們看到，這三個面向最後會匯流成同一件事：**Curry–Howard 對應**。
