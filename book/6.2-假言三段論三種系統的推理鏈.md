# 6.2 假言三段論：三種系統的推理鏈

上一節的合取交換律是「結構性的」定理：它只在連接詞的內部動手，三個系統的落差體現在**成本**上。假言三段論是本書第一次遇到**推論規則**本身的定理：它要證的不是「形狀可以互換」，而是「兩條蘊含可以疊起來」。這個區別很重要——一旦涉及蘊含，ATP 的內部表示就會露出它的本質：**歸結法其實沒有蘊含這種東西。**

本節的命題是：

$$
(P \to Q),\ (Q \to R) \;\vdash\; P \to R
$$

它就是第 2 章那條 modus ponens 鏈，只是這次我們要看清楚：**同一條鏈在三個系統裡是由什麼機制拼出來的。**

## 6.2.1 ITP：四條指令，一棵函數樹

`lean-prover` 的第二個內建範例（`lean-prover/src/lean.js:233`）：

```js
  { name: '假言三段論', src: 'theorem syllogism (h1 : P -> Q) (h2 : Q -> R) : P -> R := by\n  intro hp\n  apply h2\n  apply h1\n  exact hp' },
```

實際輸出（`node bin/cli.js --demo --trace`）：

```
theorem syllogism : P → R
  intro hp
      h1 : P → Q
      h2 : Q → R
      hp : P
      ⊢ R
  apply h2
      h1 : P → Q
      h2 : Q → R
      hp : P
      ⊢ Q
  apply h1
      h1 : P → Q
      h2 : Q → R
      hp : P
      ⊢ P
  exact hp
      沒有目標了
✔ 證明完成,核心檢查通過
```

四條指令，**逆序**前進：先 `intro hp` 把蘊含的前提引進來，再從最外層的結論 $R$ 一路往內推到 $P$ 。

這裡最值得停下來看的是 `apply` 的語意（`lean.js:147-152`）：

```js
    case 'apply': {
      const [pf, F] = app(arg, ctx), prem = []; let c = F;
      while (!eq(c, f)) { if (c.t !== 'imp') throw new Error(`apply 失敗:${fm(F)} 的結論無法吻合目標 ${fm(f)}`); prem.push(c.l); c = c.r; }
      const gs = prem.map(a => ng(ctx, a));
      return solve(gs.reduce((p, x) => ({ r: 'impE', f: p, a: M(x) }), pf), gs);
    }
```

`apply` 不是「套用一次」，而是「**沿著蘊含鏈往下走**」：它從假設的結論開始，只要還沒吻合當前目標，就剝掉一層 `imp`、把該層的前提記下來，直到結論吻合為止。所以 `apply h2` 在目標是 $R$ 時產生一個新目標 $\vdash Q$ ；如果假設是 $Q \to R \to S$ 而目標是 $S$ ，它一次就會產生**兩個**新目標。

產生的證明項是：

```
impI hp  [前提 P]
  └ impE
    ├ hyp h2
    └ impE
      ├ hyp h1
      └ hyp hp
```

用 Curry–Howard 的語言讀出來就是 $\lambda hp . h2 (h1 \, hp)$ ——**一個把 $P$ 變成 $R$ 的函式**。三段論在 ITP 裡的物理內容是：**函數合成**。

這裡有個容易被忽略的特徵：**整條推理鏈是「逆向」前進的。** `intro hp` 先把前提拉進來，然後 `apply h2` 從**結論** $R$ 開始往下剝，剝到 $P$ 才停。也就是說，ITP 的自然演繹是從「要證什麼」倒推「還缺什麼」，而不是從「已知什麼」正推「所以什麼」。

這個方向不是實作上的任意選擇，而是**命題邏輯的結構**決定的：要證 $\Gamma \vdash A$ ，最自然的做法就是問「 $A$ 的最外層是什麼規則？它的前提是什麼？」——蘊含就問「前提在哪？」，合取就問「兩半各自要證什麼？」。第 3.4 節講策略層時說過「`apply` 問的是『要證 $R$ ，我手上有 `h2 : Q \to R` ，還缺什麼？缺 $Q$ 』」——這個問句方向，就是自然演繹與核心規則之間的接口。

反過來，**如果結論對不上，`apply` 就會明確失敗**：

```js
        while (!eq(c, f)) { if (c.t !== 'imp') throw new Error(`apply 失敗:${fm(F)} 的結論無法吻合目標 ${fm(f)}`); prem.push(c.l); c = c.r; }
```

這行程式碼就是「逆向」的證明：它一路比對 `h` 的結論鏈與當前目標，一旦發現鏈上的某一層不是蘊含，就停下來報錯。換句話說，**「 $P$ 與 $Q$ 是不是同一族」這種問題，在 ITP 裡會在 `apply` 這一步就爆掉**——因為 `eq()` 比較的是完整的 AST 鍵。

## 6.2.2 λ-Cube：同一棵樹，換個皮

在 `lambda-cube` 裡，蘊含是**原生的**（`A -> B` 就是 Π 型別的表面語法），所以不需要任何定義：

```
system λ→
axiom P : Prop
axiom Q : Prop
axiom R : Prop
theorem syllogism (h1 : P -> Q) (h2 : Q -> R) : P -> R := by
  intro hp
  apply h2
  apply h1
  exact hp
```

輸出：

```
✔ theorem syllogism : (P → Q) → (Q → R) → P → R
    intro hp
        h1 : P → Q
        h2 : Q → R
        hp : P
        ⊢ R
    apply h2
        h1 : P → Q
        h2 : Q → R
        hp : P
        ⊢ Q
    apply h1
        h1 : P → Q
        h2 : Q → R
        hp : P
        ⊢ P
    exact hp
        沒有目標了
```

**注意兩份輸出的相似度驚人**——同樣的四條指令、同樣的目標變化。這不是巧合：λ-Cube 的 `apply`（`cube.js:140-150`）與 `lean.js` 的 `apply` 是同一個演算法，只是比較對象不同：

| | ITP 的 `apply` | λ-Cube 的 `apply` |
|---|---|---|
| 結論的比對 | `eq()`：公式的 α 等價 | `conv()`：型別在 βδ 下相等 |
| 前提的收集 | 沿 `imp` 鏈往下剝 | 沿 `p`（Π）節點往下剝 |
| 產生什麼 | `impE` 證明項片段 | `Ap`（應用）項片段 |
| 依賴型參數 | 不適用（蘊含不依賴） | 必須把參數寫進去，否則報錯 |

真正的差別在**核心的權威性**。ITP 的核心 `check()` 只認證明項：策略層寫錯頂多讓核心報「核心檢查失敗」；λ-Cube 的核心 `infer()`（`cube.js:94-115`）連「這個項是什麼型別」都要自己算出來，`conv` 判定（`cube.js:82-90`）還得處理 β 歸約與 δ 展開。同一個 `apply h2`，在 ITP 裡是「餵一個公式」，在 λ-Cube 裡是「做一次 β 歸約」。

這裡還有一個值得親手試一次的差別。**在 ITP 裡，公式的結構是給定的**：`h2` 的型別就是 `Q -> R`，比較時不需要任何額外工作。**在 λ-Cube 裡，型別可能藏在 `def` 後面**，這時 `apply` 必須先把它「展開」才能比較。核心的 `whnf`（`cube.js:77-81`）會做這件事：

```js
  const whnf = t => { for (;;) {
    if (t.k === 'a') { const f = whnf(t.f); if (f.k === 'l') { t = inst(f.b, t.a); continue; } return Ap(f, t.a); }
    if (t.k === 'c' && G[t.n] && G[t.n].val) { t = G[t.n].val; continue; }
    return t;
  } };
```

**這就是「δ 展開」**：`def` 的內容被代進來，直到露出真正的 Π 節點為止。於是 λ-Cube 的 `apply` 是一個「**先展開、再比較**」的程序，而 ITP 的 `apply` 是「**直接比較**」。差別在實務上不大，但概念上很重要：**λ-Cube 的核心裡沒有「公式」這種東西，只有「項」與「型別」；所有關於結構的問題，最後都變成 β 歸約與 δ 展開的問題。**

換句話說：**三段論在這兩個系統裡是同一個想法的兩種刻度，但其中一個把「想法」寫成了規則，另一個把「想法」交給了型別系統。**

## 6.2.3 ATP：三段論其實不存在

現在交給 `theorem-prover`：

```bash
node -e "
const P = require('./src/prover.js');
console.log(P.format(P.prove(['P -> Q', 'Q -> R'], 'P -> R')));
"
```

實際輸出：

```
✔ 證明成功(產生 8 個子句,0 ms)
  1. ~P | Q    [前提]
  2. ~Q | R    [前提]
  3. P    [否定結論]
  4. ~R    [否定結論]
  5. Q    [歸結 1, 3]
  7. R    [歸結 2, 5]
  8. ⊥    [歸結 7, 4]
```

**請注意第 1、2 行：`~P | Q` 與 `~Q | R` 裡已經沒有「蘊含」了。** 蘊含在子句化階段就被 NNF 展開成 $\neg P \lor Q$ （`prover.js:55`）：

```js
    case 'imp': return nnf({ t: 'or', l: { t: 'not', f: f.l }, r: f.r }, pos);
```

所以 ATP 眼裡的「三段論」根本不是三段論，而是**兩個二元子句加上兩個單位子句**。整條推理鏈是：

1. `~P | Q` 與 `P` 消去 $P$ → `Q`（第 5 條）。
2. `~Q | R` 與 `Q` 消去 $Q$ → `R`（第 7 條）。
3. `R` 與 `~R` 消去 → 空子句 $\bot$ （第 8 條）。

這三步與前兩個系統的「合成兩個函式」毫無關係。它是**文字兩兩抵消**： $\neg P$ 對上 $P$ ， $\neg Q$ 對上 $Q$ ， $R$ 對上 $\neg R$ 。ATP 之所以能把這個命題拆成子句，是因為它**已經先把蘊含拆了**，拆完之後「三段論」這個結構就不存在了，剩下的只是一堆可以互相抵消的原子。

### 一個隱含假設：三個符號屬於同一族

把命題升成一階，差距才會真正現形：

```bash
node -e "
const P = require('./src/prover.js');
console.log(P.format(P.prove(['forall x. (P(x) -> Q(x))', 'forall x. (Q(x) -> R(x))'], 'forall x. (P(x) -> R(x))')));
"
```

```
✔ 證明成功(產生 9 個子句,0 ms)
  1. ~P(X11) | Q(X11)    [前提]
  2. ~Q(X13) | R(X13)    [前提]
  3. P(sk2)    [否定結論]
  4. ~R(sk2)    [否定結論]
  5. Q(sk2)    [歸結 1, 3]
  8. R(sk2)    [歸結 2, 5]
  9. ⊥    [歸結 8, 4]
```

現在請盯著 `X11` 與 `X13`：**它們是兩個不同的變數**。第 5 條的歸結之所以成功，是因為合一把 $X11$ 綁成了 `sk2`；第 8 條的歸結之所以成功，是因為合一把 $X13$ 也綁成了 `sk2`。**「 $P$ 、 $Q$ 、 $R$ 屬於同一族謂詞、作用於同一個對象」這件事，在 ATP 裡不是被假設的，而是被「合一」逼出來的。**

這就是 ATP 的三段論與另外兩個系統的本質差異：

- ITP 與 λ-Cube 操作的是**具體命題**。它們拿到的是 $P$ 、 $Q$ 、 $R$ 三個具體的對象（或具體的型別），「它們是同一族」這個資訊由使用者保證，寫錯就編不過去。
- ATP 操作的是**文字模式**。它拿到的是 $\neg P(t) \lor Q(t)$ 這樣的模板，「它們是同一族」這個資訊必須靠**合一**在推導過程中建立起來。ATP 不會假設它，只會在需要時把它解出來。

還有兩個細節值得記下。

**第一，命題邏輯版本的 $P$ 、 $Q$ 、 $R$ 其實是「零元函數符號」。** `theorem-prover` 的解析器用一個 `bound` 陣列區分「被量詞綁定的名字」與「其餘的名字」（`prover.js:15`）：

```js
  const term = () => { const n = ident(); if (peek() === '(') { p++; return { f: n, a: args(term) }; } return bound.includes(n) ? { v: n } : { f: n, a: [] }; };
```

沒有被綁定的 `P` 會變成 `{ f: 'P', a: [] }` ——一個**沒有參數的函數符號**。所以命題邏輯版的「三段論」其實是一階邏輯的一個特例：三個不同名稱的零元謂詞。這個細節說明了一件事：**ATP 沒有「命題邏輯」這個模式**，它永遠是一階邏輯，只是有時候謂詞沒有參數。

**第二，`sk2` 是隱含地被普遍量化的。** 注意第 3、4 條子句：`P(sk2)` 與 `~R(sk2)` 。歸結是在 `sk2` 這個**特定**常量上做的，這看起來像是在證「存在某個 $x$ 使 $P(x) \wedge \neg R(x)$ 」——而不是「對所有 $x$ 」的命題。之所以這樣做仍然正確，靠的是 Herbrand 定理（第 2.4 節）：**Skolem 常量在 Herbrand 解釋下是隱含地被普遍量化的**，所以只要對它不矛盾，就對所有實例都不矛盾。

這個設計的好處是**可搜尋**：子句裡不再有量詞，搜尋空間變成一個單純的 Herbrand 宇宙。壞處是**資訊損失**：你從子句集裡讀不出「這裡原本有個 $\forall$ 」，也讀不出 `sk2` 原本是「一個任意的 $x$ 」而不是「某個特定的 $x$ 」。第 6.5 節會更仔細地談這件事。

### 對照失敗：把三段論寫反會怎樣

三段論的逆命題（ affirming the consequent ）不是定理。在 ATP 裡，我們會得到：

```bash
node -e "
const P = require('./src/prover.js');
console.log(P.format(P.prove(['forall x. (P(x) -> Q(x))'], 'forall x. (Q(x) -> P(x))')));
"
```

```
✘ 無法證明:子句集已飽和,結論不是前提的邏輯後果
```

**注意 ATP 對「證不出來」的說法**：它說「子句集已飽和」，而不是「這個命題是假的」。第 4.1 節說過，這個區別是 ATP 的先天缺陷——**「我沒找到」不等於「不存在」**。而在 ITP 裡，同樣的失敗會長成完全不同的樣子：使用者會被卡在某個目標上，核心會指出「exact 的型別不吻合」。**一個是語意空洞的答案，一個是可操作的錯誤訊息。**

順帶一提，量詞也一樣被吃掉了：`forall x. (P(x) -> Q(x))` 的全稱量詞在子句化後變成一個**自由變數** `X11`（第 4.3 節的 Skolem 化），而結論 `forall x. (P(x) -> R(x))` 被否定之後變成 `∃x. (P(x) ∧ ¬R(x))` ，Skolem 化成一個**常量** `sk2`。整個「對所有 $x$ 」的語意，被壓縮成「有一個特定的 $x$ （那個 `sk2`）」。

## 6.2.4 對照小結

| | ITP | λ-Cube | ATP |
|---|---|---|---|
| 「蘊含」是什麼 | AST 裡的 `imp` 節點 | Π 型別 | 子句化時被展開掉的東西 |
| 三段論的實際動作 | `apply` 沿 `imp` 鏈剝殼 | `apply` 沿 Π 剝殼 | 兩次單位子句對撞 |
| 證明行數 | 4 條指令 | 4 條指令 | 8 個子句（3 次歸結） |
| 「 $P$ 、 $Q$ 、 $R$ 同族」誰保證 | 使用者寫死的具體命題 | 使用者寫死的具體型別 | **合一在推導中建立** |
| 失敗時的訊息 | `apply 失敗:Q → R 的結論無法吻合目標 R` | `apply 失敗:(Q → R) 的結論無法吻合目標 R` | `✘ 無法證明:子句集已飽和,結論不是前提的邏輯後果` |
| 隱含風險 | 目標與假設搞混 | 依賴型參數沒寫出來 | 量詞被 Skolem 化後語意改變 |

三段論在 ATP 裡**退化成了量詞消去與合一**。這是本章第一個「同一個定理、三種本質」的案例，而它也預告了下一節的主題：只要邏輯裡有古典性的成分，三個系統的價碼就會徹底分開。

把三條推理鏈並排看，可以得到本節最重要的一個對照：

- **ITP 的鏈是「一條規則一條規則疊起來的」**：每一層 `impE` 都是一個明確的推理動作，讀者可以逐步複述「我用 $h_2$ 得到 $Q$ ，用 $h_1$ 得到 $P$ 」。
- **λ-Cube 的鏈是「同一件事的 λ 項」**：整條鏈壓縮成 $\lambda hp . h2 (h1 \, hp)$ ，讀者要懂 Curry–Howard 對應才能把它還原成推理。
- **ATP 的鏈是「文字抵消的記錄」**：它不描述推理，只描述「哪些文字被消掉了」。三段論這個結構在鏈裡已經不見蹤影。

三段論在 ATP 裡**退化成了量詞消去與合一**——具體地說：全稱量詞變成自由變數、蘊含變成子句、而「 $P$ 推 $Q$ 推 $R$ 所以 $P$ 推 $R$ 」變成「用合一把 `sk2` 綁進兩條子句，然後看它們會不會撞」。**三段論的「三」在哪裡？不在任何一步裡，而在子句被切開之前的那個形狀上。**

下一節我們加入否定，並且第一次遇到「有些定理在一個系統裡證得出、在另一個系統裡證不出」的情形：雙重否定消去。ITP 與 ATP 都能做，λ-Cube 卻必須自己選擇要不要古典。
