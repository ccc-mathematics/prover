# 6.3 雙重否定消去：直觀主義的壁與兩種跨越方式

前兩節的定理在三個系統裡都「trivial 地」成立。從這一節開始，題目帶上了**否定**，而否定帶來三個系統第一次真正的分歧：本節的命題

$$
\neg\neg P \;\to\; P
$$

在直觀主義邏輯裡**不是定理**。它叫「雙重否定消去」（double negation elimination, DNE），是「從否定命題的否定得到命題」——用一句話說就是「如果我證不出 $\neg P$ ，那我就證明了 $P$ 」。直覺上很自然，但直觀主義不承認。

本節要做三件事：先用 Kripke 語義說清楚**為什麼直觀主義不承認**；再看 ITP 與 ATP 各自**怎麼繞過**這道壁；最後看 λ-Cube 為什麼**沒有牆可繞**——它連否定都得自己寫。

## 6.3.1 Kripke 模型：牆長什麼樣

直觀主義語義用「世界」與「偏序」來解釋命題：世界 $w$ 記作 $w \models P$ 表示「在 $w$ 這個階段， $P$ 已經成立」，而且有**單調性**——若 $w \models P$ 且 $v \supseteq w$ ，則 $v \models P$ （一旦成立就永遠成立）。

考慮只有兩個世界的小模型：

| | $w_0$ | $w_1$ |
|---|---|---|
| $P$ | 不成立 | **成立** |
| $\neg P$ | 不成立 | 不成立 |
| $\neg\neg P$ | **成立** | 成立 |

逐格檢查：

- 在 $w_1$ ： $P$ 成立，所以 $\neg P$ 不成立（否則就要一個不成立 $P$ 的未來世界，與單調性矛盾）。
- 在 $w_0$ ： $\neg P$ **不成立**，因為它的未來世界 $w_1$ 滿足 $P$ 。
- 在 $w_0$ ： $\neg\neg P$ **成立**，因為 $w_0$ 的兩個未來世界（ $w_0$ 自己與 $w_1$ ）都不滿足 $\neg P$ 。

於是 $w_0 \models \neg\neg P$ 但 $w_0 \not\models P$ ：** $\neg\neg P \to P$ 在這個模型裡被反駁了。**

直觀的解釋是： $\neg\neg P$ 只告訴我們「 $P$ 遲早會成立」，不保證「現在就成立」。在 $w_0$ 這個「還沒搞清楚」的階段，我們知道再等一步就能確定 $P$ ，但我們此刻還不能下手用它。反過來說，**若 $\neg\neg P$ 在所有世界都成立，那麼 $P$ 也在所有世界都成立**——這正是 Kripke 語義中 DNE 失敗的精確位置。

這個模型不是證明工具，而是**測量工具**：它告訴我們「直觀主義的牆」有多寬——寬到連「否定否定」都跨不過去。

## 6.3.2 ITP：一條策略，藏起一個核心規則

`lean-prover` 的第四個內建範例（`lean-prover/src/lean.js:235`）：

```js
  { name: '雙重否定消去(古典)', src: 'theorem dne : ~~P -> P := by\n  intro h\n  by_contra hn\n  exact h hn' },
```

實際輸出：

```
theorem dne : ¬¬P → P
  intro h
      h : ¬¬P
      ⊢ P
  by_contra hn
      h : ¬¬P
      hn : ¬P
      ⊢ False
  exact h hn
      沒有目標了
✔ 證明完成,核心檢查通過
```

三條指令，第三條 `exact h hn` 只是把兩個假設餵進去。**真正的動作藏在 `by_contra` 裡。** 策略層的那一行是（`lean.js:157`）：

```js
    case 'by_contra': { const h = ws[0] || 'h', neg = { t: 'imp', l: f, r: BOT }, n = ng([...ctx, [h, neg]], BOT); return solve({ r: 'dne', p: { r: 'impI', h, f: neg, p: M(n) } }, [n]); }
```

它做四件事：把當前目標 $A$ 變成否定 $\neg A = A \to \bot$ ；把 $\neg A$ 當作假設 `hn` 放進上下文；把目標換成 $\bot$ ；並且**把整段證明包成一個 `dne` 節點**。

而核心對這個節點的檢查是（`lean.js:98`）：

```js
    case 'dne': { const f = need(C(p.p), 'imp', '反證'); return f.r.t === 'bot' && f.l.t === 'imp' && f.l.r.t === 'bot' ? f.l.l : bad('反證需要 ¬¬A'); }
```

這一行就是「牆」在程式裡的所在。核心檢查三件事：子證明是蘊含、蘊含的結論是 $\bot$ 、蘊含的前提是 $\bot \to \bot$ 的形狀——也就是說**子證明的型別必須是 $\neg\neg A$ ** ——然後回傳 $A$ 。

整個證明項因此是：

```
impI h  [前提 ¬¬P]
  └ dne
    └ impI hn  [前提 ¬P]
      └ impE
        ├ hyp h
        └ hyp hn
```

`dne` 節點是**整個 `lean-prover` 中唯一一個沒有 Curry–Howard 對應的規則節點**。拿掉它（核心刪一行、策略刪一行），剩下的系統就是一個直觀主義的自然演繹證明器，除了 `dne` 與 `peirce` 兩個定理之外照樣能用。

**這是 ITP 買古典性的價格，而且價格相當公道：使用者寫 `by_contra` 的時候完全感覺不到自己在使用古典邏輯。** 古典性被集中到一個可見的點上，而不是滲透到每一條規則裡。

## 6.3.3 ATP：古典是它的「免費午餐」

把同一個命題交給 `theorem-prover`：

```bash
node -e "
const P = require('./src/prover.js');
console.log(P.format(P.prove([], '~~P -> P')));
"
```

```
✔ 證明成功(產生 3 個子句,0 ms)
  1. P    [否定結論]
  2. ~P    [否定結論]
  3. ⊥    [歸結 2, 1]
```

**零條指令、零條特別規則、三個子句、一步歸結。** 這就是 ATP 的免費午餐：它的核心規則（歸結）本來就是**古典邏輯**的規則，否定只是 NNF 化時的一個對偶運算（`prover.js:50-59`）：

```js
function nnf(f, pos) {
  switch (f.t) {
    case 'atom': return pos ? f : { t: 'not', f };
    case 'not': return nnf(f.f, !pos);
    case 'and': case 'or': return { t: (f.t === 'and') === pos ? 'and' : 'or', l: nnf(f.l, pos), r: nnf(f.r, pos) };
    case 'imp': return nnf({ t: 'or', l: { t: 'not', f: f.l }, r: f.r }, pos);
    case 'iff': return nnf({ t: 'and', l: { t: 'imp', l: f.l, r: f.r }, r: { t: 'imp', l: f.r, r: f.l } }, pos);
    default: return { t: (f.t === 'all') === pos ? 'all' : 'ex', v: f.v, f: nnf(f.f, pos) };
  }
}
```

`nnf` 的最後一行是關鍵：**否定被推成對偶量詞**（ $\forall$ 變 $\exists$ ，反之亦然），這是**古典對偶律**。整個 NNF 化的過程假設了「否定可以自由地穿過量詞」，正是直觀主義拒絕的那件事。

因此，ATP 裡的「否定」不是一個可以選擇要不要的東西——它是語意的地基。使用者**無法**在這個系統裡寫出一個直觀主義的證明，因為：

1. 歸結這條規則本身就不是直觀主義有效的；
2. NNF 化（連同 Skolem 化）假設的是古典語意；
3. 反駁法的骨架是「證明 $\Gamma \cup \{\neg A\}$ 不可滿足」，而「不可滿足」的語意也是古典的。

所以 ATP 的古典性是「**免費午餐**」也是「**隱藏假設**」：它藏在 NNF 化與歸結這兩處你幾乎不會去讀的地方。使用者永遠不會在寫下命題的時候被問「你要古典的嗎」。

## 6.3.4 λ-Cube：連否定都要自己動手

而且這個隱含假設**不止一處**。第 4.3 節的 Skolem 化是第二處：`skolem()` 把 $\exists$ 換成一個 Skolem 函數（`prover.js:60-67`），而「 $\exists x . P(x) \to P(c)$ 在直觀主義裡不成立」——所以 Skolem 化同樣是古典假設。**兩處假設、同一個根源：這個系統的語意從一開始就是古典的。**

這與 ITP 的做法恰好相反：它把古典性**集中成一個節點**（`lean.js:98`），其餘部分維持直觀主義。**集中與分散，是兩種完全不同的工程風格**，而它們各自的優劣點在本章的每一節裡都會浮現：集中的版本容易被審查（ITP），分散的版本容易被忽略（ATP）。

`lambda-cube` 的核心是純粹的 Π 型別系統。它的規則集由 `system` 指令決定（`cube.js:5-6`），而**無論選哪個頂點，都沒有任何與否定有關的規則**。 $\forall$ 是 Π 型別（內建）， $\exists$ 要自己定義（`cube.js:246`），否定更是連影子都沒有。

所以第一步是**自己寫否定**。最接近 `lean-prover` 的寫法是：

```
system λω
axiom P : Prop
axiom Q : Prop
axiom False : Prop
def Not (A : Prop) : Prop := A -> False
```

接著嘗試證明 $\neg\neg P \to P$ ：

```
theorem dne_try : Not (Not P) -> P := by
  intro h
  exact h
```

實際輸出：

```
✘ theorem dne_try : Not (Not P) → P
    intro h
        h : Not (Not P)
        ⊢ P
    第 9 行:exact 的型別不吻合:
      得到 Not (Not P)
      需要 P
      h : Not (Not P)
      ⊢ P
```

**證不出來，而且這不是 bug，是設計。** λ-Cube 的核心是直觀主義的（Π 型別的規則完全符合直觀主義邏輯），所以 $\neg\neg P \to P$ 在它裡面**本來就不該證得出來**。

要想在 λ-Cube 裡使用雙重否定消去，唯一的辦法是**把它當公理宣告出來**：

```
axiom classic : forall (A : Prop), Not (Not A) -> A
theorem dne : Not (Not P) -> P := by
  apply classic P
```

輸出：

```
✔ axiom classic : ∀ (A : Prop), Not (Not A) → A
✔ theorem dne : Not (Not P) → P
    apply classic P
        沒有目標了
```

一行指令。但請認真看待這件事：**`apply classic P` 與 ITP 的 `by_contra hn` 在「證明成本」上完全相同，在「信任結構」上卻完全不同。**

- ITP 的 `by_contra` 是一條**可執行的推導規則**：核心會檢查它的形狀、用它導出的命題參與後續推理。核心裡確實多了一條非直觀主義的規則。
- λ-Cube 的 `apply classic P` 是**一條被接受的假設**：核心只是在型別檢查時看到一個公理常數。整個系統的邏輯強度完全取決於使用者宣告了什麼。

這就是「核心不預設邏輯」這句話的兩面：**自由**是你可以宣告任何邏輯（直觀主義、古典、模理論的片段）；**負擔**是邏輯強度不再由系統保證，而是由你的宣告清單決定。Coq 與 Lean 正是走這條路——它們的核心同樣是直觀主義的（Π 型別），而 `Classical` 模組把 DNE、排中律、二次否定等等古典原理**逐一列成公理**，讓使用者自己選。

順帶提一個容易踩到的坑：另一種常見的 Church 編碼是 `def Not (A : Prop) : Prop := forall (C : Prop), A -> C`（「強否定」）。它看起來更「Church」，但**用它寫出來的 $\neg\neg P \to P$ 證不出來，而且理由和上面完全不同**。實際嘗試：

```
system λω
axiom P : Prop
def Not (A : Prop) : Prop := forall (C : Prop), A -> C
theorem dne_try2 : Not (Not P) -> P := by
  intro h
  apply h P
  intro n
  intro a
  exact (n P a)
```

輸出：

```
✘ theorem dne_try2 : Not (Not P) → P
    intro h
        h : Not (Not P)
        ⊢ P
    apply h P
        h : Not (Not P)
        ⊢ Not P
    intro n
        h : Not (Not P)
        n : Prop
        ⊢ P → n
    intro a
        h : Not (Not P)
        n : Prop
        a : P
        ⊢ n
    第 9 行:n 不是函數,它的型別是 Prop
```

**請看 `intro n` 之後的這一行：`n : Prop`，目標是 `P → n`。** 也就是說，這個 `intro` 引進來的不是一個「證明」，而是一個**型別變數**——因為 $\forall C : Prop$ 的外層量化對象是型別。整個 `Not P` 裡的第一層量詞是「對所有型別 $C$ 」，這與 `A -> False` 裡的 $\bot$ 是完全不同的東西。

於是「 $P$ 是假的」這個意思被悄悄換掉了：在這個編碼下，`Not P` 其實是「** $P$ 對所有型別都有用**」，它甚至在 $P$ 為真時也可被造出來（給定任何 $C$ 都回傳同一個 $P$ ）。**用它寫出來的 $\neg\neg P$ 不是直觀主義的雙重否定，更不是古典的雙重否定**，所以「用它能不能談論古典性」這個問題本身就問錯了。

否定編碼的選擇不是自由的：**編碼方式決定了你寫下的符號到底代表什麼**。這一點在第 6.6 節談德摩根律時還會再出現一次——那裡三個系統處理「否定」的三種方式（展開、對偶化、編碼）會並排出現。

## 6.3.5 對照小結

| | ITP | ATP | λ-Cube |
|---|---|---|---|
| 否定從哪來 | 解析期展開成 `A -> ⊥` | NNF 化的對偶運算 | 自己 `def Not` |
| 系統的邏輯 | 直觀主義 + 一條 `dne` 規則 | **天生古典** | 純粹直觀主義（Π 型別） |
| 證明 DNE 的成本 | 3 條指令（其中 `by_contra` 是古典性的來源） | 0 條指令 | 1 條公理 + 1 條指令 |
| 古典性藏在哪 | 核心的 `dne` 案例（`lean.js:98`） | `nnf()` 的對偶律 + 歸結規則 | **使用者宣告的公理清單** |
| 失敗時的訊息 | `核心檢查失敗:反證需要 ¬¬A` | `✘ 無法證明:子句集已飽和,結論不是前提的邏輯後果` | `exact 的型別不吻合:`（得到 `Not (Not P)`，需要 `P`） |
| 能不能寫直觀主義的證明 | 能（不用 `by_contra` 即可） | **不能** | 能（這是預設） |

三種價格，可以這樣總結：

- **ITP 的價格是「核心多一條規則」。** 代價可控，而且集中在 `lean.js:98` 那一行；使用者甚至可以把它刪掉，得到一個純直觀主義的證明器。
- **ATP 的價格是「邏輯被藏起來」。** 代價是零，但代價的位置不可見——你無法在這個系統裡證明一個直觀主義的命題，甚至無法問「這是直觀主義的嗎」。
- **λ-Cube 的價格是「你要自己宣告」。** 代價是把邏輯選擇權交還給使用者；好處是同一個核心可以承載不同強度的邏輯，壞處是系統的強度不再由程式保證。

最後一點值得展開：**「能不能關掉古典性」是三個系統最實際的差別。** 在 ITP 裡，只要刪掉 `check()` 的一個 `case` 與策略層的一個 `case`，`lean-prover` 就是一個直觀主義證明器（`dne` 與 `peirce` 兩個範例會失敗，其餘照用）。在 λ-Cube 裡，把 `axiom classic` 那一行刪掉就同樣有效。**但在 ATP 裡沒有開關**——要得到一個直觀主義的歸結法，你得重寫 `nnf()` 與 `skolem()`，也就是重寫整個語意基礎。**這個差別，是「核心小、假設集中」這種設計原則最實際的回報。**

下一節我們把古典性再推一步：Peirce 定律 $(\left(P \to Q\right) \to P) \to P$ 。它是本專案裡**最長**的一個 ITP 證明（在 `lean.js:236`），卻是 ATP 裡**最短**的一個（3 個子句）。同一個定理，兩個系統的「長度」竟然相差一個數量級——這會迫使我們重新思考「證明長度」到底測量了什麼。
