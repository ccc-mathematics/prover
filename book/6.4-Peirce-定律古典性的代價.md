# 6.4 Peirce 定律：古典性的代價

第 6.3 節的雙重否定消去讓我們看到古典性可以在三個系統裡用三種方式取得，但那一個定理太簡單了，看不出「代價」。本節挑一個更有壓力的例子：Peirce 定律

$$
\left(\left(P \to Q\right) \to P\right) \to P
$$

它是 Peirce 本人寫下的形式（與蘋果那句 slogan 押韻的是同名的另一位 Peirce）。它是「排中律 $P \lor \neg P$ 」的等价物之一，也是直觀主義與古典邏輯分歧最尖銳的地方之一：**它在直觀主義裡不成立，在古典裡成立，而且它在 ITP 裡是本專案最長的一個證明，在 ATP 裡卻是最短的一個。**

在本專案裡，這個定理同時是 `lean-prover` 的第五個內建範例（`lean-prover/src/lean.js:236`）與 `theorem-prover` 的第三個內建範例（`theorem-prover/src/prover.js:214`）：

```js
  { name: 'Peirce’s law', premises: [], goal: '((P -> Q) -> P) -> P' },
```

兩個系統把它放在同一個位置，是有意的：**它是我們的「壓力測試」**。

## 6.4.1 ITP：七條指令，兩個閘門

`lean-prover` 的 Peirce 證明是這樣的（`lean-prover/src/lean.js:236`）：

```js
  { name: 'Peirce’s law', src: 'theorem peirce : ((P -> Q) -> P) -> P := by\n  intro h\n  by_contra hn\n  apply hn\n  apply h\n  intro hp\n  exfalso\n  exact hn hp' },
```

實際輸出（`node bin/cli.js --demo --trace`）：

```
theorem peirce : ((P → Q) → P) → P
  intro h
      h : (P → Q) → P
      ⊢ P
  by_contra hn
      h : (P → Q) → P
      hn : ¬P
      ⊢ False
  apply hn
      h : (P → Q) → P
      hn : ¬P
      ⊢ P
  apply h
      h : (P → Q) → P
      hn : ¬P
      ⊢ P → Q
  intro hp
      h : (P → Q) → P
      hn : ¬P
      hp : P
      ⊢ Q
  exfalso
      h : (P → Q) → P
      hn : ¬P
      hp : P
      ⊢ False
  exact hn hp
      沒有目標了
✔ 證明完成,核心檢查通過
```

逐行拆解，並指出每一行為什麼是合法的：

- **`intro h`**：目標是蘊含，把前提 $(P \to Q) \to P$ 放進上下文。證明項片段 `impI`。
- **`by_contra hn`**：**第一個閘門**。目標 $P$ 被換成 $\bot$ ，上下文多出 `hn : ¬P`（內部是 $P \to \bot$ ）。證明項片段是 `dne`（`lean.js:157`）。到這裡為止，這一步還不能保證什麼——它只是把「我要證 $P$ 」換成「我要證 $P$ 是假的話會炸」，並且**預先承諾**最後會用 `dne` 收尾。
- **`apply hn`**：`hn : ¬P` 就是 $P \to \bot$ ，所以「要證 $\bot$ ，我缺一個 $P$ 」。目標變成 $\vdash P$ 。證明項片段 `impE`。
- **`apply h`**：`h : (P \to Q) \to P` ，所以「要證 $P$ ，我缺一個 $P \to Q$ 」。目標變成 $\vdash P \to Q$ 。
- **`intro hp`**：目標變成 $\vdash Q$ ，上下文多出 `hp : P`。
- **`exfalso`**：**第二個閘門**。此時手上同時有 `hp : P` 與 `hn : ¬P` ，矛盾已經成立，所以可以從 $\bot$ 推出任何東西——包括目標 $Q$ 。證明項是 `botE`（`lean.js:97`）：

```js
    case 'botE': need(C(p.p), 'bot', '⊥ 消去'); return p.f;
```

  這裡有個細節值得注意：`botE` 的結論 `p.f` **不是核心算出來的**，而是策略層預先放進去的（`lean.js:156`）。核心只檢查前提確實是 $\bot$ ，然後直接回傳那個預先宣告的結論。這在邏輯上是完全合理的—— $\bot$ 可以推出任何東西——但它提醒我們：核心回傳的東西，未必是它推導出來的。

  策略層那一行是：

```js
    case 'exfalso': { const n = ng(ctx, BOT); return solve({ r: 'botE', p: M(n), f }, [n]); }
```

  `f` 就是當時的目標。**策略層把目標抄進證明項，核心就直接把它當成結論回傳。** 這是「核心回傳的可能是證明項自己宣告的東西」的一個實例——第 3.3 節提過，這在爆炸律上是合理的，但在其他規則上就會是危險的做法。第 7 章談核心設計時，我們會回頭看這個設計選擇。

  從數學上看，`exfalso` 這一步省掉的是什麼？Peirce 定律的標準古典證明是：

  1. 反設 $\neg P$ ；
  2. 由 $\neg P$ 得到 $P \to Q$ （因為 $\neg P$ 蘊含 $\bot$ ，而 $\bot \to Q$ 恆真）；
  3. 套用前提得 $P$ ；
  4. 與 $\neg P$ 矛盾，故 $\neg\neg P$ ；
  5. 由 DNE 得 $P$ 。

  ITP 的證明把第 2 步與第 4 步**壓縮成一句** `exfalso`：既然 $P$ 與 $\neg P$ 同時在手，就不必真的把 $Q$ 造出來。**爆炸律在這裡扮演的角色是「讓矛盾直接結案」。**
- **`exact hn hp`**：`hn : ¬P` 吃 `hp : P` ，得到 $\bot$ 。證明項是 `impE`。

完整證明項：

```
impI h  [前提 (P → Q) → P]
  └ dne
    └ impI hn  [前提 ¬P]
      └ impE
        ├ hyp hn
        └ impE
          ├ hyp h
          └ impI hp  [前提 P]
            └ botE  [結論 Q]
              └ impE
                ├ hyp hn
                └ hyp hp
```

**這棵樹裡有兩個「非直觀主義」的閘門**：`dne`（第 6.3 節）與 `botE`（爆炸律）。直觀主義邏輯裡爆炸律其實是有效的（ $\bot$ 推任何東西），所以真正的非經典成分只有 `dne` 一個；但在**證明的長度**上，`exfalso` 這一步是關鍵——它讓我們不必真的把 $Q$ 造出來。

順帶比較一下 ITP 與 ATP 對「古典性」的處理位置：ITP 把 `dne` 放在核心的第 98 行，一行；ATP 則把它藏起來了。

## 6.4.2 ATP：三個子句，硬碰硬

`theorem-prover` 的 Peirce 範例輸出是：

```
== Peirce’s law
✔ 證明成功(產生 3 個子句,0 ms)
  1. P    [否定結論]
  2. ~P    [否定結論]
  3. ⊥    [歸結 2, 1]
```

**三個子句，一次歸結。** 讓我們把子句化過程攤開，因為過程本身比結果更有教學價值。

否定結論是 $\neg\left(\left(\left(P \to Q\right) \to P\right) \to P\right)$ ，也就是 $\left(\left(P \to Q\right) \to P\right) \wedge \neg P$ 。NNF 化後：

- $\left(\left(P \to Q\right) \to P\right)$ 展開成 $\neg\left(P \to Q\right) \lor P$ ，再展開成 $(P \wedge \neg Q) \lor P$ 。分配律一跑，CNF 化得到兩個子句：`P` 與 `P | ~Q`。
- $\neg P$ 得到子句 `~P`。

初始子句集因此是三條：`P`、`P | ~Q`、`~P`。**但輸出裡只有兩條。** 原因是 `accept()` 的包含檢查（`prover.js:149`）：

```js
    for (const c of active.concat(passive)) if (c.lits.length <= l.length && subsumes(c.lits, l)) return null;
```

單位子句 `P` 包含了 `P | ~Q` ，後者被剪掉了。**於是 ATP 的證明裡，Peirce 定律那個最複雜的部分—— $(P \to Q) \to P$ ——被整個吸收、蒸發、不留痕跡。**

剩下的兩條子句 `P` 與 `~P` 正面相撞，產生空子句 $\bot$ 。

這是一個非常值得停下來的思想實驗：**ATP 證明 Peirce 定律的過程中，完全沒有「使用」那條蘊含假設。** 它之所以能證，是因為「否定 Peirce 定律」這個命題本身不可滿足——而不可滿足的理由只用到 $P$ 與 $\neg P$ 。ATP 不會告訴你「我用了定理的哪一部分」；它只會給你一條矛盾鏈。

順帶一提，排中律在 ATP 裡同樣是免費的：

```
✔ 證明成功(產生 3 個子句,2 ms)
  1. ~P    [否定結論]
  2. P    [否定結論]
  3. ⊥    [歸結 1, 2]
```

這是 `prove([], 'P | ~P')` 的輸出。**排中律在古典邏輯裡不是定理，而是公理；在 ATP 裡它連公理都不用寫，因為否定結論 `~(P | ~P)` 會被 NNF 化成 $\neg P \wedge P$ ，然後自己撞掉。**

## 6.4.3 λ-Cube：核心最小，但證明最稠密

現在來到最沒有「免費午餐」的系統。λ-Cube 的核心是純粹的 Π 型別系統，否定、 $\bot$ 、排中律全部要自己宣告。第 6.3 節已經建立了兩條公理：

```
system λω
axiom P : Prop
axiom Q : Prop
axiom False : Prop
def Not (A : Prop) : Prop := A -> False
axiom classic : forall (A : Prop), Not (Not A) -> A
axiom exfalso : forall (A : Prop), False -> A
```

有了 `classic`（雙重否定消去）與 `exfalso`（爆炸律），Peirce 定律就可以證了：

```
theorem peirce : ((P -> Q) -> P) -> P := by
  intro h
  have hnn : Not (Not P) := fun (hnp : Not P) => hnp (h (fun (hp : P) => exfalso Q (hnp hp)))
  exact (classic P hnn)
```

實際輸出：

```
✔ theorem peirce : ((P → Q) → P) → P
    intro h
        h : (P → Q) → P
        ⊢ P
    have hnn : Not (Not P) := fun (hnp : Not P) => hnp (h (fun (hp : P) => exfalso Q (hnp hp)))
        h : (P → Q) → P
        hnn : Not (Not P)
        ⊢ P
    exact (classic P hnn)
        沒有目標了
```

**三條策略指令，但其中一條是一個四層嵌套的 λ 項。** 我們把它拆開讀：

1. `fun (hnp : Not P) => ...`：要造出 $\neg\neg P$ ，先假裝手上有一個 $\neg P$ （記作 `hnp`），目標是造出 `False`。
2. `hnp hp`：`hnp : P → False` 吃一個 `P` 就得到 `False`。所以只要能造出一個 `P` 就完成了。
3. `h (fun (hp : P) => exfalso Q (hnp hp))`：`h` 需要一個 `P → Q` 當 argument。我們給它 `fun (hp : P) => exfalso Q (hnp hp)`——收到 `P` 之後，用 `hnp hp` 得到 `False`，再用爆炸律 `exfalso Q` 得到 `Q`。所以這個函數確實是 `P → Q` ✓。
4. 整個 `h (...)` 因此得到一個 `P` ，餵給 `hnp` 得到 `False` ✓。

**這就是「核心小但證明長」的真正含義。** λ-Cube 的核心 `infer()` 只有二十行，它連「否定是什麼」都不知道；但正因如此，使用者必須在一個項裡同時安排：反證法的結構、爆炸律的使用、以及兩個否定編碼的配合。ITP 的 Peirce 證明有七行、每一行都平凡到不需要思考；λ-Cube 的 Peirce 證明只有三行，但其中一行需要讀者自己完成第 6.3 節那套「從 $\neg\neg P$ 造出 $P$ 」的推理。

這裡有一個值得停下來的對照：**「證明的長度」在兩個系統裡量的是不同的東西。** 在 ITP 裡，長度量的是「推理步驟的數目」，每一步對應一條核心規則，所以長度可以當成「這個證明用了几條規則」的代理指標。在 λ-Cube 裡，長度量的是「項的結構大小」，而一個項可以把任意多步推理壓縮成一個 β 歸約鏈——**λ 項裡的嵌套深度對應的是推理的「深度」，不是「步數」**。

所以兩個系統裡「最長的證明」根本不是同一種東西：ITP 的 Peirce 是「步子最多」，λ-Cube 的 Peirce 是「步子最多但被壓縮成三行」。**如果用行數當作跨系統比較的指標，就會把「表達的密度」誤認成「推理的深度」。** 這也是本章每一節都堅持把三份產物**一起**攤出來看的原因：只看行數，會錯得很離譜。

## 6.4.4 對照小結

| | ITP | λ-Cube | ATP |
|---|---|---|---|
| 證明長度 | 7 條指令（每行平凡） | 3 條指令（其中 1 行是密集項） | 3 個子句（1 次歸結） |
| 古典性的來源 | 核心的 `dne` 規則（`lean.js:98`） | 兩條使用者公理 `classic`、`exfalso` | NNF 對偶律 + 歸結規則 |
| 定理的哪個部分被用到 | 全部： $(P \to Q) \to P$ 與 $\neg P$ 都用上了 | 全部 | **只有 $P$ 與 $\neg P$ **； $(P \to Q) \to P$ 被子句包含剪掉 |
| 產物的可讀性 | 一棵可以逐節點朗讀的樹 | 一個可以逐字展開的項 | 一條「文字兩兩抵消」的鏈 |
| 失敗時的訊息 | `核心檢查失敗:反證需要 ¬¬A` | `exact 的型別不吻合:`（多行） | `✘ 無法證明:子句集已飽和,結論不是前提的邏輯後果` |

三個系統在 Peirce 定律上的表現，可以濃縮成一句話：**它們都「證出來了」，但它們對「證明」這個詞的定義相差甚遠。**

- ITP 的證明是**一條可逐行檢查的推理鏈**：每一個節點對應一條推理規則，核心會逐一驗證。讀者可以從證明項還原出「人做了什麼」。
- λ-Cube 的證明是**一個可被執行的項**：核心只檢查型別，讀者要從型別還原出「人做了什麼」——而這需要懂 Curry–Howard 對應。
- ATP 的證明是**一條矛盾鏈**：它證明了「前提加上否定結論不可滿足」，至於「為什麼不可滿足」，由子句之間的抵消關係解釋。它甚至沒有用到定理的全部結構。

這三種「證明」都可以說是「被機器檢查過的」，但它們檢查的東西完全不同。回到第 1.1 節那個中心問題——**當我們說「一個命題已被證明」時，機器究竟檢查了什麼？**——Peirce 定律的三份產物給出了三個不同的答案。

## 6.4.5 為什麼 Peirce 是分歧的試金石

在古典邏輯裡，Peirce 定律、排中律 $P \lor \neg P$ 、雙重否定消去 $\neg\neg P \to P$ 這三者是互相可推的。它們是同一塊古幣的三個面：**「承認矛盾必假」這一件事有多種說法**。

三個系統因此在「能不能證明排中律」上分歧：

- **ITP 能**，而且不打算讓你選擇——`dne` 在核心裡，你用了 `by_contra` 就是用了它。
- **ATP 能**，而且同樣不給你選擇——NNF 的對偶律把古典性焊死在核心裡。
- **λ-Cube 的預設不能**，但它**允許你開啟**：宣告 `classic` 與 `exfalso` 兩條公理，系統立刻獲得古典性；不宣告，就維持直觀主義。

第三種態勢是前兩種沒有的。Coq 與 Lean 走的正是第三種路：核心直觀主義，古典邏輯放在一個獨立的模組裡，使用者 `Require Import Classical.` 之後才取得。這不是工程上的偷懶，而是把第 6.3 節那個問題「要不要古典」從系統管理者的層級，交到每個使用者的手上。

三種態勢各有一個很實際的後果。**ITP 的狀態**適合教學與稽核：核心只有一條非直觀主義規則，審查者一眼就能看出系統有多強。**ATP 的狀態**適合大批量求解：使用者不需要理解邏輯細節，只要命題寫對了就行。**λ-Cube 的狀態**適合做基礎設施：同一個核心可以承裝直觀主義、古典、乃至模理論的片段，Coq 的 `Classical` 模組正是這樣一個「可選的古典性套件」。三種狀態沒有優劣之分，只有**適用場景**之分。

下一節加入量詞。這會是三個系統分歧最大的地方：ITP 用分支機制處理 $\exists$ 的消去，λ-Cube 用 Church 編碼定義 $\exists$ ，ATP 則用 Skolem 化把它整個消掉。**同一個量詞，三種截然不同的物理處理。**
