# 6.6 德摩根與對偶性：量詞的否定

前五節的對照都還在「同一個命題、三種證明」的框架裡。本節要處理一個特別的定理族：**德摩根律**。

$$
\neg(P \wedge Q) \;\leftrightarrow\; \neg P \lor \neg Q
$$

$$
\neg\forall x\, P(x) \;\leftrightarrow\; \exists x\, \neg P(x)
$$

德摩根律之所以特別，是因為它**不是關於某個邏輯系統的定理，而是關於「否定」這件事本身的說明**：它說明否定是那個把 $\wedge$ 變成 $\lor$ 、把 $\forall$ 變成 $\exists$ 的**對偶運算**。

這就讓它成為三個系統差異的絕佳探針：**看一個系統怎麼處理否定，就知道它怎麼理解整個邏輯。** 三個系統的答案是三種：

- **ITP：展開。** 否定在解析期就被換成 $A \to \bot$ ，德摩根律變成一條**必須手寫證明的定理**。
- **ATP：對偶化。** `nnf()` 在把否定推入公式時，**直接把 $\wedge$ 與 $\lor$ 互換、 $\forall$ 與 $\exists$ 互換**——德摩根律被「內建」在轉換函式裡。
- **λ-Cube：編碼。** 否定與連接詞全是 Π 型別的定義，德摩根律變成「**兩個定義之間的等價**」，而不是任何內建規則的推論。

## 6.6.1 ITP：核心不認識德摩根，所以你要自己證

`lean-prover` 的核心裡沒有德摩根律。它認識的只有： $\to$ 、 $\wedge$ 、 $\lor$ 、 $\bot$ 、 $\forall$ 、 $\exists$ ，以及它們的消去／引入規則。而解析期做過兩次關鍵的展開（`lean.js:23` 與 `lean.js:17`）：

```js
    if (x === '~') { p++; return { t: 'imp', l: un(), r: BOT }; }
```

```js
  const iff = () => { let l = imp(); while (T[p] === '<->') { p++; const r = imp(); l = { t: 'and', l: { t: 'imp', l, r }, r: { t: 'imp', l: r, r: l } }; } return l; };
```

所以 $\neg A$ 變成 $A \to \bot$ ， $A \leftrightarrow B$ 變成 $(A \to B) \wedge (B \to A)$ 。**德摩根律在這個系統裡必須被證明，而且證明它需要手動做「消去的引入」。**

這裡有一個容易被忽略的對稱性：**因為 $\neg$ 在 ITP 裡是一個「定義」（定義成 $A \to \bot$ ），所以德摩根律在 ITP 裡是「關於這個定義的一條定理」。** 它不是邏輯的必然，而是「如果用 $A \to \bot$ 當否定，那麼德摩根律就成立」這個條件式。λ-Cube 裡的 Church 編碼同樣是定義，只是那個定義更複雜，所以等價更難寫。**兩個系統都把否定變成了「可以選擇的東西」，因此都必須把德摩根律的內容還給使用者。**

先看直觀主義就能證的那半邊： $\neg P \lor \neg Q \to \neg(P \wedge Q)$ 。

```
theorem dm2 : (~P | ~Q) -> (~(P & Q)) := by
  intro h
  intro hp
  cases hp with p q
  cases h with a b
  exact a p
  exact b q
```

輸出（節錄）：

```

  intro h
      h : ¬P ∨ ¬Q
      ⊢ ¬(P ∧ Q)
  intro hp

      2 個目標

      hp : P ∧ Q

```

這裡有一個值得停下來看的地方：**`intro hp` 之後，`hp : P ∧ Q` 是一個合取假設，而目標是 $\bot$ 。** 要用它，必須先 `cases hp with p q` 把合取拆開——**德摩根律的證明裡出現了「消去的引入」**，因為 ITP 的核心不會自動把 $\neg(P \wedge Q)$ 變成 $\neg P \wedge \neg Q$ 。在 ATP 裡，那正是 NNF 化顺手做掉的事。

再看需要古典性的那一半： $\neg(P \wedge Q) \to \neg P \lor \neg Q$ 。

```
theorem dm1 : (~(P & Q)) -> (~P | ~Q) := by
  intro h
  by_contra hn
  apply hn
  right
  intro hq
  apply hn
  left
  intro hp
  apply h
  constructor
  exact hp
  exact hq
```

輸出（節錄）：

```
theorem dm1 : ¬(P ∧ Q) → ¬P ∨ ¬Q
  intro h
      h : ¬(P ∧ Q)
      ⊢ ¬P ∨ ¬Q
  by_contra hn
      h : ¬(P ∧ Q)
      hn : ¬(¬P ∨ ¬Q)
      ⊢ False
  apply hn
      h : ¬(P ∧ Q)
      hn : ¬(¬P ∨ ¬Q)
      ⊢ ¬P ∨ ¬Q
  right
      ...
      ⊢ ¬Q
  intro hq
      hq : Q
      ⊢ False
  apply hn
      ⊢ ¬P ∨ ¬Q
  left
      ⊢ ¬P
  intro hp
      hp : P
      ⊢ False
  apply h
      ⊢ P ∧ Q
  constructor
      2 個目標
      ⊢ P
      ⊢ Q

  exact hq
      沒有目標了

```

**十二條指令。** 讓我們追蹤它為什麼需要這麼多：

1. `by_contra hn` 假設 $\neg(\neg P \lor \neg Q)$ ，把目標換成 $\bot$ （**用到 DNE**）。
2. `apply hn` 把目標換回 $\neg P \lor \neg Q$ ——注意這是**第二次**用到 `hn` 。
3. `right` 選 $\neg Q$ 那一邊。
4. `intro hq` 假設 $Q$ ，目標回到 $\bot$ 。
5. `apply hn` 又一次把目標換成 $\neg P \lor \neg Q$ 。
6. `left` 選 $\neg P$ 那一邊，`intro hp` 假設 $P$ ，目標 $\bot$ 。
7. `apply h` 把 $P \wedge Q$ 拿回來，`constructor` 拆成 $P$ 與 $Q$ 兩個目標，`exact hp` 與 `exact hq` 收尾。

這十三行的推理骨架，用白話說就是：「假設 $\neg P \lor \neg Q$ 為假（**用 DNE**），那麼 $\neg Q$ 為假、 $P$ 為真，於是 $P \wedge Q$ 為真，但前提說 $P \wedge Q$ 為假，矛盾。」

**在 ITP 裡證明德摩根律，本質上就是手寫一次 DNE 的應用。** 這也讓我們重新看第 6.3 節的結論：ITP 的古典性是「集中在一條規則上」，但在**定理層面**它並不省事——每次用到否定的地方，你都要把那條規則的代價付一遍。

### 量詞版本的德摩根

第二條德摩根律 $\neg\forall x\, P(x) \leftrightarrow \exists x\, \neg P(x)$ 在 ITP 裡更貴，因為它同時用到 $\forall$ 與 $\exists$ 的消去：

```
theorem dq2 : (exists x. ~P(x)) -> (~(forall x. P(x))) := by
  intro h
  intro hn
  cases h with x hx
  apply hx
  exact hn x
```

輸出（節錄）：

```
theorem dq2 : (∃ x, ¬P(x)) → ¬(∀ x, P(x))
  intro h
      h : ∃ x, ¬P(x)
      ⊢ ¬(∀ x, P(x))
  intro hn
      h : ∃ x, ¬P(x)
      hn : ∀ x, P(x)
      ⊢ False
  cases h with x hx
      x : 項
      h : ∃ x, ¬P(x)
      hn : ∀ x, P(x)
      hx : ¬P(x)
      ⊢ False
  apply hx
      ⊢ P(x)
  exact hn x
      沒有目標了
✔ 證明完成,核心檢查通過
```

這裡 `apply hx` 把 $\neg P(x) = P(x) \to \bot$ 用掉，剩下要證 $P(x)$ ，而 `exact hn x` 正好用 $\forall$ 消去拿出 $P(x)$ 。**兩個量詞的消去被疊在一起，中間隔著一個 $\to$ 消去**——這是本專案裡量詞與否定交錯最緊湊的一個片段。

反方向（ $\neg\forall x P(x) \to \exists x\, \neg P(x)$ ）需要 DNE，而且需要**兩次**：

```
theorem dq1 : (~(forall x. P(x))) -> (exists x. ~P(x)) := by
  intro h
  by_contra hn
  apply hn
  exists socrates
  intro hp
  apply h
  intro y
  by_contra hy
  apply hn
  exists y
  exact hy
```

輸出（節錄）：

```
theorem dq1 : ¬(∀ x, P(x)) → ∃ x, ¬P(x)
  intro h
      h : ¬(∀ x, P(x))
      ⊢ ∃ x, ¬P(x)
  by_contra hn
      h : ¬(∀ x, P(x))
      hn : ¬(∃ x, ¬P(x))
      ⊢ False
  apply hn
      ⊢ ∃ x, ¬P(x)
  exists socrates
      ⊢ ¬P(socrates)
  intro hp
      hp : P(socrates)
      ⊢ False
  apply h
      ⊢ ∀ x, P(x)
  intro y
      y : 項
      ⊢ P(y)
  by_contra hy
      hy : ¬P(y)
      ⊢ False
  apply hn
      ⊢ ∃ x, ¬P(x)
  exists y
      ⊢ ¬P(y)
  exact hy
      沒有目標了
✔ 證明完成,核心檢查通過
```

**十一條指令，兩次 `by_contra`。** 這裡有一個細節非常值得注意：`by_contra hy` 出現在 `intro y` **之後**，也就是說它對**目標 $P(y)$ ** 使用 DNE，而不是對整個定理的結論使用。這正是第 6.3 節提過的現象：`by_contra` 的 `dne` 節點只能套用在「當前目標」上，所以**多次使用 DNE 需要多次 `by_contra`**。這與 ATP 形成鮮明對比——ATP 的 DNE 是整個推論系統的性質，用多少次都不需要額外宣告。

## 6.6.2 ATP：德摩根被寫在轉換函式裡

在 ATP 裡，德摩根律**不需要被證明**，因為它被實作成 `nnf()` 的一部分（`theorem-prover/src/prover.js:54` 與 `:57`）：

```js
    case 'and': case 'or': return { t: (f.t === 'and') === pos ? 'and' : 'or', l: nnf(f.l, pos), r: nnf(f.r, pos) };
```

```js
    default: return { t: (f.t === 'all') === pos ? 'all' : 'ex', v: f.v, f: nnf(f.f, pos) };
```

讀這兩行的方式是：當 `pos` 為 `false`（也就是我們在否定裡）時， $\wedge$ 變成 $\lor$ 、 $\lor$ 變成 $\wedge$ 、 $\forall$ 變成 $\exists$ 、 $\exists$ 變成 $\forall$ ——**這就是德摩根律，一字不差。**

所以 ATP 處理否定的方式是「**對偶化**」：它不是證明德摩根律，而是**用它**。讓我們看實際輸出：

```bash
node -e "
const P = require('./src/prover.js');
console.log(P.format(P.prove([], '~(P & Q) <-> (~P | ~Q)')));
console.log(P.format(P.prove([], '~(forall x. P(x)) <-> (exists x. ~P(x))')));
"
```

```
✔ 證明成功(產生 6 個子句,2 ms)
  1. ~P | ~Q    [否定結論]
  2. P    [否定結論]
  3. Q    [否定結論]
  4. ~Q    [歸結 1, 2]
  6. ⊥    [歸結 4, 3]
```

```
✔ 證明成功(產生 8 個子句,0 ms)
  1. ~P(sk1) | ~P(sk2)    [否定結論]
  4. P(X5) | P(X6)    [否定結論]
  5. P(X9)    [因子化 4]
  6. ~P(sk2)    [歸結 1, 5]
  8. ⊥    [歸結 6, 5]
```

第一個證明裡的四條子句值得逐條看：

- 第 1 條 `~P | ~Q` 來自否定結論的其中一半。
- 第 2、3 條 `P` 與 `Q` 是**單獨**的子句——它們來自否定結論裡的 $P \wedge Q$ ，被 CNF 化**分配**開了。
- 第 4 條 `~Q` 是 `~P | ~Q` 與 `P` 歸結的結果。
- 第 6 條 $\bot$ 是 `~Q` 與 `Q` 歸結的結果。

**整個證明裡沒有任何一步是「德摩根」。** 德摩根發生在更早的地方——在子句化之前，`nnf()` 把 $\neg(P \wedge Q)$ 變成 $\neg P \lor \neg Q$ ，把 $\neg(P \lor \neg Q)$ 變成 $\neg P \wedge \neg Q$ ，然後 CNF 化把後者拆成 `~P` 與 `~Q` 兩條。**ATP 是「用到德摩根」，而不是「證明德摩根」。**

把這條轉換鏈整條寫出來會更清楚。否定結論 $\neg\left(\neg(P \wedge Q) \leftrightarrow (\neg P \lor \neg Q)\right)$ 經過 NNF 與 CNF 之後是這樣的：

1. $\leftrightarrow$ 展開成 $(\neg(P \wedge Q) \to (\neg P \lor \neg Q)) \wedge ((\neg P \lor \neg Q) \to \neg(P \wedge Q))$ ；
2. 否定分配進去， $\wedge$ 變 $\lor$ 、 $\lor$ 變 $\wedge$ ；
3. 德摩根作用在 $\neg(P \wedge Q)$ 上，得到 $\neg P \lor \neg Q$ ；作用在 $\neg(\neg P \lor \neg Q)$ 上，得到 $\neg P \wedge \neg Q$ ；
4. CNF 分配律把 $\wedge$ 拆開， $\lor$ 留著。

剩下的子句正是輸出裡看到的那幾條：`~P | ~Q` （第 1 條）、`P` 與 `Q` （第 2、3 條），以及被包含檢查剪掉的 `~P` 、 `~Q` 兩條。**整個德摩根律的內容，落在第 3 步的那兩次「把 $\wedge$ 換成 $\lor$ 」上。**

第二個證明更有意思：第 1 條子句 `~P(sk1) | ~P(sk2)` 裡有**兩個不同的 Skolem 常量**。那是因為 $\leftrightarrow$ 被展開成 $(A \to B) \wedge (B \to A)$ ，兩邊各有一個 $\exists$ ，Skolem 化分別給了它們 `sk1` 與 `sk2` 。第 4 條 `P(X5) | P(X6)` 則是 $\neg\forall x P(x)$ 的對偶形狀——原本的 $\forall$ 在否定裡變成 $\exists$ ，再變成 Skolem 化後的兩個自由變數。

## 6.6.3 λ-Cube：德摩根是兩個定義的等價

λ-Cube 裡沒有否定，也沒有連接詞。要談德Morgan，必須先把三樣東西都定義出來：

```
system λω
axiom P : Prop
axiom Q : Prop
axiom False : Prop
def Not (A : Prop) : Prop := A -> False
def And (A B : Prop) : Prop := forall (C : Prop), (A -> B -> C) -> C
def Or (A B : Prop) : Prop := forall (C : Prop), (A -> C) -> (B -> C) -> C
```

在這個設定下，德摩根律變成一個關於**定義**的命題：「`Not (And P Q)` 與 `Or (Not P) (Not Q)` 是不是同一件事？」

直觀主義能證的那半邊（對應 ITP 的 `dm2`）：

```
theorem dm_intuitive : Or (Not P) (Not Q) -> Not (And P Q) := by
  intro h
  intro hpair
  have hp : P := hpair P (fun (p : P) (q : Q) => p)
  have hq : Q := hpair Q (fun (p : P) (q : Q) => q)
  apply h False
  intro np
  exact np hp
  intro nq
  exact nq hq
```

輸出（節錄）：

```
✔ theorem dm_intuitive : Or (Not P) (Not Q) → Not (And P Q)
    intro h
        h : Or (Not P) (Not Q)
        ⊢ Not (And P Q)
    intro hpair
        h : Or (Not P) (Not Q)
        hpair : And P Q
        ⊢ False
    have hp : P := hpair P (fun (p : P) (q : Q) => p)
        hp : P
        ⊢ False
    have hq : Q := hpair Q (fun (p : P) (q : Q) => q)
        hq : Q
        ⊢ False
    apply h False
        2 個目標
        
        ⊢ Not P → False
        ⊢ Not Q → False
    intro np
        np : Not P
        ⊢ False
    exact np hp
    intro nq
        nq : Not Q
        ⊢ False
    exact nq hq
        沒有目標了
```

**九條指令，但每一條都在做「型別層」的事。** 兩個關鍵步驟值得拆開：

- **`have hp : P := hpair P (fun (p : P) (q : Q) => p)`**：要從一個 Church 編碼的合取 `And P Q` 裡**取出** $P$ 這一半，得用「把它實例化成 $P$ 自己」的老把戲：`hpair P` 把延續的目標型別設成 $P$ ，然後給它一個 `P → Q → P` 的函數（忽略 $Q$ ，回傳 $P$ ）。**在 AST 裡這是一個欄位讀取；在 Church 編碼裡這是一個 CPS 的自我應用。**
- **`apply h False`**：`Or A B` 的定義是 $\forall C:Prop$ ， $(A \to C) \to (B \to C) \to C$ ，所以要「使用」它，就必須**指定延續的目標型別**。這裡指定的是 `False` ——因為我們要證 $\bot$ 。

**注意 ITP 與 λ-Cube 在這一點上的呼應**：ITP 的 `intro hp` 把 $P \wedge Q$ 拆成 `p` 與 `q` 兩條假設，λ-Cube 的 `hpair P (...)` 把合取「投影」出來。**兩者做的是同一件事：從一個合取裡取出兩半。** 差別在於 ITP 把它寫成核心的一條規則，λ-Cube 把它寫成使用者要重複的延續技巧。

反方向（ $\neg(P \wedge Q) \to \neg P \lor \neg Q$ ）在這個設定下**需要古典性**，與 ITP 的 `dm1` 完全一致：λ-Cube 的核心是直觀主義的，沒有 `classic` 公理就證不出來。

### 為什麼說「德摩根在型別論裡不是定理而是定義的等價」

把三個系統的處理方式並排，就會發現一個更根本的差異：

| | 德摩根律的地位 |
|---|---|
| ITP | 一條**必須證明**的定理；核心不含它，證明它要付 DNE 的代價 |
| ATP | 一條**被內建**的轉換規則；`nnf()` 就是德摩根的實作 |
| λ-Cube | 一條**兩個定義之間的等價**；`And`、`Or`、`Not` 都是 Π 型別的定義，證明等價要寫延續 |

在 ATP 裡，德摩根是**轉換規則**；在 ITP 裡，它是**定理**；在 λ-Cube 裡，它是**兩個定義的等價性**。這三種地位對應三種不同的「可被質疑性」：

- 規則不能被質疑（你只能改程式）；
- 定理可以被質疑（你得給出證明）；
- 定義之間的等價可以被質疑（你得寫出轉換，而且不同的人會寫出不同的轉換）。

## 6.6.4 對照小結

| | ITP | ATP | λ-Cube |
|---|---|---|---|
| 否定怎麼處理 | **展開**：解析期換成 $A \to \bot$ | **對偶化**：`nnf()` 把否定推成對偶量詞 | **編碼**：自己 `def Not` |
| 德摩根律的地位 | 必須證明的定理 | 內建在 `nnf()` 裡的轉換 | 兩個 Church 定義之間的等價 |
| 命題邏輯版德摩根 | 12 行 + 6 行（其中一半要 DNE） | 6 個子句（2 次歸結） | 9 行（直觀主義那半邊） |
| 量詞版德摩根 | 11 行 + 5 行（要兩次 `by_contra`） | 8 個子句（含 Skolem 化） | 需自行用 `def Ex` 編碼，並依賴 `classic` |
| 證明時是否用到德摩根 | **用到**（要自己證） | **用到**（NNF 自動套用） | **用到**（要自己編碼等價） |
| 失敗時的訊息 | `exact 的型別不吻合:得到 …,但目標是 …` | `✘ 無法證明:子句集已飽和,結論不是前提的邏輯後果` | `exact 的型別不吻合:`（多行，含「得到／需要」） |

**三種否定處理方式的後果，一句話總結：**

- **展開**（ITP）把否定變成一個普通的公式，於是所有關於否定的定理都要**手動重新證明**。好處是核心規則極少（每條規則都只處理「一個前提、一個結論」），壞處是定理層的開銷。
- **對偶化**（ATP）把否定變成一個**轉換層的運算**，於是德摩根之類的定律被免費提供。壞處是整個系統被焊死在古典語意上，而且這個假設藏在你通常不會讀的那個函式裡。
- **編碼**（λ-Cube）把否定變成一個**你定義的東西**，於是「否定是什麼」變成一個設計決定。自由，但你要自己承擔所有後果——包括第 6.3 節那個「強編碼其實不是否定」的坑。

下一節是最後一節，也是最能說明「三個系統不是同一個東西」的一節：**等式**。ATP 把它當一等公民（甚至有專門的參數替換規則），ITP 連表達都做不到，而 λ-Cube 有一個漂亮的編碼（Leibniz 等式）卻缺少宇宙層級。三者的落差，會從「行數」變成「能不能說話」。
