# 9.3 λ-Cube：腳本語法與系統表

λ-Cube 是三個系統裡最「小」的一個：它沒有命題邏輯、沒有一階量詞、沒有等式，只有型別。所有東西——包括 $\wedge$ 、 $\lor$ 、 $\exists$ 、 $\bot$ ——都是用 Π 型別定義出來的。本節給出腳本的六種指令、項的語法、策略速查表、八個 λ-Cube 頂點的規則表，以及一份「這個系統做不到什麼」的清單。

## 9.3.1 六種指令

指令由 `runScript()`（`cube.js:168-222`）辨識，辨識規則是一條正則（`cube.js:172`）：

```js
const starts = []; L.forEach((l, i) => /^(def|theorem|axiom|check|eval|system)\b/.test(l) && starts.push(i));
```

**指令必須寫在行首**（前面不能有空白），而且一行只能有一個指令。一個指令的「區塊」從它那一行延伸到下一個指令出現之前；`theorem` 的區塊裡，標頭之後的行就是策略腳本。

| 指令 | 寫法 | 做什麼 | 原始碼 |
|---|---|---|---|
| `system` | `system λC` | 切換 λ-Cube 的頂點 | `cube.js:181` |
| `axiom` | `axiom 名稱 : 型別` | 宣告一個公理（只有型別，沒有值） | `cube.js:214` |
| `def` | `def 名稱 (x : A) : B := 項` | 宣告一個定義（透明，可被展開） | `cube.js:210-213` |
| `theorem` | `theorem 名稱 (h : A) : B := by` + 策略行 | 宣告並證明一個定理 | `cube.js:185-207` |
| `check` | `check 項` | 印出項與它的型別 | `cube.js:183-184` |
| `eval` | `eval 項` | 印出項的正規形與它的型別 | `cube.js:183-184` |

下面每個指令都配一個可以直接貼進 `node bin/cli.js` 的例子。

### `system`：選擇頂點

```
system λC
```

輸出一行規則清單：

```
✔ system λC  規則:Prop>Prop  Type>Prop  Prop>Type  Type>Type
```

規則清單由 `setSys()`（`cube.js:170`）組出：

```js
const setSys = n => { if (!CUBE[n]) throw new Error(`未知的系統 ${n},可用:${Object.keys(CUBE).join(' ')}`); sys = n; rules = new Set(['Prop>Prop', ...CUBE[n]]); K = kernel(G, rules, fl); };
```

注意 `Prop>Prop` **永遠**在規則集裡；系統名只是決定「額外」的規則。系統名寫錯會得到「未知的系統 X,可用:λ→ λ2 λP λω_ λP2 λω λPω_ λC」。

### `axiom`：宣告公理

```
axiom P : Prop
```

`axiom` 的型別可以帶 Π（`cube.js:214` 走的是 `wrap(Pi, bs, ty)`），所以只要 `Nat` 與 `Vec` 都已宣告過，下面這行就是合法的：

```
axiom Nat : Prop
axiom succ : Nat -> Nat
axiom Vec : Nat -> Prop
axiom cons : forall (n : Nat), Vec n -> Vec (succ n)
```

### `def`：宣告定義

```
def id : forall (A : Prop), A -> A := fun (A : Prop) (x : A) => x
```

`def` 會做兩件事：宣告型別，並且保存**值**（`cube.js:213`：`G[name] = { ty: pis, val };`）。保存值是 `def` 與 `theorem` 的關鍵差別——`def` 是透明的，核心化簡時會把它展開（`cube.js:79`：`if (t.k === 'c' && G[t.n] && G[t.n].val) { t = G[t.n].val; continue; }`）。

### `theorem`：宣告並證明

```
axiom P : Prop
theorem id_p : P -> P := by
  intro h
  exact h
```

`theorem` 的標頭**可以跨行**（`cube.js:186`）：

```js
let h = s; while (h < e && !/:=\s*by\s*$/.test(L[h])) h++;
```

也就是說 `:= by` 出現在哪一行，標頭就到哪一行結束。前提的括號用 `binders()`（`cube.js:53-60`）解析，可以一次寫多個：`(A B : Prop)` 會產生兩個綁定。

### `check`：看型別

```
check id
```

輸出 `✔ check id : ∀ (A : Prop), A → A`。`check` 呼叫 `K.infer([], t)` 取得型別，但**不做化簡**。

### `eval`：看正規形

```
eval id (forall (B : Prop), B -> B) id
```

輸出：

```
✔ eval fun (A : Prop) => fun (x : A) => x : ∀ (B : Prop), B → B
```

`eval` 呼叫 `K.nf(t)`，也就是先做 β 歸約再做 δ 展開（`cube.js:91`）。

## 9.3.2 項的語法

項的解析器在 `parser()`（`cube.js:37-72`）。它認得的節點只有六種：變數 `v`、sort `s`、常數 `c`、應用 `a`、λ 抽象 `l`、Π 型別 `p`（外加策略用的洞 `m` 與 `sorry` 的 `z`）。

| 寫法 | 範例 | AST | 說明 |
|---|---|---|---|
| 變數 | `x`、`h1'` | `v` | 必須在上下文裡，否則報「未定義的名稱」 |
| 常數 | `P`、`id` | `c` | 必須是 `axiom`／`def` 宣告過的名字 |
| sort | `Prop`、`Type` | `s` | 只有這兩個 |
| 應用 | `f a b`、`f (a b)`、`f a` | `a` | `app()`（`cube.js:51`）反覆套用 `atom()` |
| λ 抽象 | `fun (x : A) => t` | `l` | 也接受 `fun (x : A), t` 與 `fun (x : A). t` |
| Π 型別 | `forall (x : A), B` | `p` | 也接受 `forall (x : A). B` |
| 箭頭 | `A -> B` | `p` | `arrow()`（`cube.js:52`）把 `->` 轉成 Π |

別名由 `tok()`（`cube.js:35`）處理：

```js
const tok = s => s.replace(/λ/g, ' fun ').replace(/[Π∀]/g, ' forall ').replace(/→/g, '->').replace(/⇒/g, '=>').match(/:=|->|=>|[A-Za-z_][\w']*|\S/g) || [];
```

| 別名 | 展開成 |
|---|---|
| `λ` | `fun` |
| `Π`、`∀` | `forall` |
| `→` | `->` |
| `⇒` | `=>` |

**binder 的分隔符號**有三種可用（`cube.js:65`）：`=>`（fun 專用）、`,` 或 `.`。也就是說 `fun (x : A) => t`、`fun (x : A), t`、`fun (x : A). t` 都對。

**sort 的階層**只有兩層，而且方向是固定的（`cube.js:97`）：

```js
case 's': if (t.s === 'Prop') return Sx('Type'); throw E('Type 沒有型別(λ-cube 的最頂層)');
```

| 對象 | 結果 |
|---|---|
| `Prop` | 型別是 `Type` |
| `Type` | **沒有型別**，寫 `check Type` 會被核心拒絕 |
| `Prop` 裡的項 | 其 sort 是 `Prop` |
| `Type` 裡的項 | 其 sort 是 `Type` |

### 兩個小陷阱

**應用的括號。** `f a b` 是三個 token 組成的應用鏈，但 `f (a b)` 也行——`atom()`（`cube.js:42-50`）遇到 `(` 就遞迴解析一個完整的項。

**`Prop` 與 `Type` 是保留字。** `isId()`（`cube.js:36`）把它們排除在識別字之外，所以 `Prop` 永遠是 sort，不會被當成宣告過的常數。

## 9.3.3 策略速查

策略層在 `tactic()`（`cube.js:120-164`），只有六條。比 `lean-prover` 少很多，因為 λ-Cube 沒有命題連接詞——`intro` 同時處理 $\to$ 與 $\forall$ （兩者都是 Π），`exact` 同時處理所有命題。

| 策略 | 適用目標 | 參數 | 產生什麼證明項 | 原始碼 |
|---|---|---|---|---|
| `intro` | 目標是 $\to$ 或 $\forall$ | 可選名稱；`intro a b` 一次引入多個 | `Lm`（λ 抽象） | `cube.js:128-133` |
| `exact` | 任何 | 一個項 | 該項本身 | `cube.js:134-138` |
| `apply` | 目標是某項型別的結論 | 一個項 | `Ap`（應用） | `cube.js:140-150` |
| `assumption` | 目標與某假設型別相同 | 無 | `V`（變數） | `cube.js:139` |
| `have` | 任何 | `have 名稱 : 型別` 或 `have 名稱 : 型別 := 項` | `Ap(Lm(...), ...)` | `cube.js:151-160` |
| `sorry` | 任何 | 無 | `z`（sorry 節點） | `cube.js:161` |

### `intro`

```js
case 'intro': {
  if (ws.length > 1) return ws.forEach(w => tactic(K, G, S, 'intro', w));
  const T = K.whnf(g.ty); if (T.k !== 'p') throw new Error(`intro 失敗:目標 ${show(g.ty, ns)} 不是 → 或 ∀`);
  const n = ws[0] || (T.n === '_' ? 'h' : T.n), ng = mk([...ctx, { n, ty: T.ty }], T.b);
  return solve(Lm(n, T.ty, Mv(ng.id)), [ng]);
}
```

三個重點。第一，**名字可以省略**：目標是箭頭（綁定名是 `_`）時預設叫 `h`，目標是 `forall (x : A), B` 時直接沿用 `x`。第二，**`intro a b` 可以一次做兩次**（第一行）。第三，核心層不需要區分 $\to$ 與 $\forall$ ——它們都是 Π 節點。

### `exact`

```js
case 'exact': {
  const t = prs(arg), ty = K.infer(ctx, t);
  if (!K.conv(ty, g.ty)) throw new Error(`exact 的型別不吻合:\n  得到 ${show(ty, ns)}\n  需要 ${show(g.ty, ns)}`);
  return solve(t);
}
```

判斷用的是 `conv()`（`cube.js:82-90`），它做結構相等加 β/δ 展開。**注意它是雙向的定義等價，不是語法相等**——這就是 `def` 透明、`theorem` 不透明的差別。

### `apply`

`apply` 把「被套用項的型別」一層一層剝開，直到結論與目標 `conv` 相等：

```js
case 'apply': {
  const t = prs(arg), T0 = K.infer(ctx, t), prem = []; let cur = T0;
  while (!K.conv(cur, g.ty)) {
    cur = K.whnf(cur);
    if (cur.k !== 'p') throw new Error(`apply 失敗:${show(T0, ns)} 的結論無法吻合目標 ${show(g.ty, ns)}`);
    if (uses(cur.b)) throw new Error('apply 遇到依賴型參數(∀),請把參數寫進去,例如 apply h C');
    prem.push(cur.ty); cur = shift(cur.b, -1);
  }
  const gs = prem.map(ty => mk(ctx, ty));
  return solve(gs.reduce((p, x) => Ap(p, Mv(x.id)), t), gs);
}
```

`while` 迴圈每次剝掉一層 Π，把被剝掉的前件變成新的目標。所以 `apply` 產生的證明項是巢狀的 `Ap`。

**`apply` 遇到依賴型參數時會主動擋下來**（`cube.js:145`）：

```
apply 遇到依賴型參數(∀),請把參數寫進去,例如 apply h C
```

原因在 `uses(cur.b)`（`cube.js:15`）：如果 Π 的**函數體**用到了被綁定的變數，那這個 Π 就是依賴型別的，`apply` 無法在不猜參數的情況下把它拆開。舉個實際的例子：

```
system λP
axiom Nat : Prop
axiom succ : Nat -> Nat
axiom Vec : Nat -> Prop
axiom v : forall (n : Nat), Vec n
theorem t : forall (n : Nat), Vec (succ n) := by
  apply v
```

輸出：

```
✘ theorem t : ∀ (n : Nat), Vec (succ n)
    第 7 行:apply 遇到依賴型參數(∀),請把參數寫進去,例如 apply h C
      ⊢ ∀ (n : Nat), Vec (succ n)
```

修法是把參數寫進去：`apply v n`。

### `assumption`

```js
case 'assumption': { for (let j = d; j--; ) if (K.conv(shift(ctx[j].ty, d - j), g.ty)) return solve(V(d - 1 - j)); throw new Error('找不到符合目標的假設'); }
```

它從最近的假設往前找，型別 `conv` 相同就回傳那個變數。找不到的訊息是「找不到符合目標的假設」。

### `have`

`have` 有兩種形式。**沒有值**的形式產生**兩個**目標（先證明那個型別，再繼續原本的目標）：

```
axiom P : Prop
axiom Q : Prop
theorem t : P -> Q := by
  intro hp
  have hq : Q
  sorry
  exact hq
```

**有值**的形式只產生一個目標：

```
axiom P : Prop
axiom Q : Prop
axiom pq : P -> Q
theorem t : P -> Q := by
  intro hp
  have hq : Q := pq hp
  exact hq
```

兩者的區別在 `cube.js:155` 的 `val !== undefined` 分支：有值時直接用該項當作 λ 抽象的身體，沒有值時身體是一個洞，要你自己解掉。

### `sorry`

`sorry` 產生一個 `z` 節點。核心推導它的型別時會設 `fl.sorry = true`（`cube.js:99`），整個定理的狀態因此變成 `sorry` 而不是 `done`。

## 9.3.4 八個頂點的規則表

`CUBE` 表在 `cube.js:5-6`，是整個 λ-Cube 的開關：

```js
const CUBE = { 'λ→': [], 'λ2': ['Type>Prop'], 'λP': ['Prop>Type'], 'λω_': ['Type>Type'], 'λP2': ['Type>Prop', 'Prop>Type'],
  'λω': ['Type>Prop', 'Type>Type'], 'λPω_': ['Prop>Type', 'Type>Type'], 'λC': ['Type>Prop', 'Prop>Type', 'Type>Type'] };
```

規則 `X>Y` 的意思是：**允許形成一個 Π 型別，其定義域的 sort 是 $X$ 、值域的 sort 是 $Y$ **。核心的檢查在 `cube.js:103`：

```js
if (!rules.has(s1 + '>' + s2)) throw E(`目前的系統不允許這個 Π 型別:定義域屬於 ${s1},值域屬於 ${s2}(缺少規則 ${s1}>${s2}):${show(t, names(ctx))}`);
```

| 系統 | `CUBE` 裡的額外規則 | 完整規則集 | 能力 |
|---|---|---|---|
| `λ→` | （無） | `Prop>Prop` | 簡單型別；只有命題層的 Π |
| `λ2` | `Type>Prop` | `Prop>Prop`、`Type>Prop` | 多型（System F）：定義域是 `Type`、值域是命題 |
| `λP` | `Prop>Type` | `Prop>Prop`、`Prop>Type` | 依值型別：定義域是命題、值域是型別（型別族） |
| `λω_` | `Type>Type` | `Prop>Prop`、`Type>Type` | 型別運算子：定義域與值域都是 `Type` |
| `λP2` | `Type>Prop`、`Prop>Type` | `Prop>Prop`、`Type>Prop`、`Prop>Type` | 多型 + 依值型別 |
| `λω` | `Type>Prop`、`Type>Type` | `Prop>Prop`、`Type>Prop`、`Type>Type` | 多型 + 型別運算子 |
| `λPω_` | `Prop>Type`、`Type>Type` | `Prop>Prop`、`Prop>Type`、`Type>Type` | 依值型別 + 型別運算子 |
| `λC` | `Type>Prop`、`Prop>Type`、`Type>Type` | `Prop>Prop`、`Type>Prop`、`Prop>Type`、`Type>Type` | 三者全開：Calculus of Constructions |

三個維度是獨立的：多型（`Type>Prop`）、依值型別（`Prop>Type`）、型別運算子（`Type>Type`），三條軸各開或關，得到 $2^3 = 8$ 個頂點。第 5.5 節把這張表攤開來談。

**這張表有兩個必須知道的陷阱。**

第一，**λ2 的多型其實是「定義域在 Type 裡、值域是命題」**。`def id : forall (A : Prop), A -> A` 的 Π 定義域是 `Prop` 這個 sort（它的 sort 是 `Type`），值域 `A -> A` 的 sort 是 `Prop`，所以需要 `Type>Prop`——這就是 λ2 才有、λ→ 沒有的東西，也是 `lambda-cube/test/test.js:5` 測的：

```
λP 沒有多型,拒絕 ∀(A:Prop)
```

第二，**`λω_` 與 `λω` 的差别不在 `Type>Type`**，而在 `Type>Prop`：λω_ 只有 `Type>Type`，λω 才有 `Type>Prop`。第 5.5 節指出，這個實作裡 `Type>Type` 這條規則只能拿 `Prop` 去用，真正 kinds 的 $\mathit{Type} : \mathit{Type}$ 其實缺席。

第三，**`λ→` 並非完全沒有 Π**：`Prop>Prop` 永遠在規則集裡，所以命題層的函式型別（例如 `P -> Q`）在任何系統都可用。

## 9.3.5 已知限制速查

| 限制 | 症狀 | 原始碼 |
|---|---|---|
| **沒有歸納型別** | 無法定義 `Nat`、`List` 之類的代數資料型別；所有東西都得用 Church 編碼硬寫 | 全檔無相關節點 |
| **沒有宇宙階層** | `Type` 沒有型別，`check Type` 直接被核心拒絕 | `cube.js:97` |
| **沒有 η 規則** | `conv` 只做結構相等加 β/δ，`fun (x : A) => f x` 與 `f` 不相等 | `cube.js:82-90` |
| **沒有隱含參數** | `id` 必須寫成 `id P`；`apply` 遇到依賴型參數直接擋下 | `cube.js:145` |
| **`def` 不能遞迴** | `whnf` 展開 `def` 的值是無條件的，遞迴的 `def` 會讓核心無限展開 | `cube.js:79` |
| **`theorem` 不透明** | `theorem` 只存型別不存值，核心不會展開它；因此 `theorem` 不能用來證明等價命題 | `cube.js:190` |
| **化簡不是最佳化** | `conv` 是「定義等價」，大型項會很慢 | `cube.js:82-90` |

`def` 不能遞迴這條值得展開講：核心的 `whnf()`（`cube.js:77-81`）是無條件地把 `G[t.n].val` 換回項本身。它沒有「是否正在展開中」的守衛，也沒有大小遞減的檢查。所以

```
def loop : Nat -> Nat := fun (n : Nat) => loop n
```

這種定義一旦被 `conv` 碰到，就會無限展開下去。真正的系統用「Guardedness 檢查」或「結構遞迴」來解決，第 8.1 節會說明。

## 9.3.6 四個狀態燈號

λ-Cube 的狀態集合比 ITP 少一個（`cube.js:227`）：

```js
const ICON = { ok: '✔', sorry: '⚠', open: '…', error: '✘' };
```

| 狀態 | 燈號 | 一句話 | 原始碼 |
|---|---|---|---|
| `ok` | ✔ | 這條指令成功；定理的話是核心驗證通過 | `cube.js:220` |
| `sorry` | ⚠ | 證明裡有 `sorry` 節點 | `cube.js:205` |
| `open` | … | 腳本跑完了但還有目標沒解 | `cube.js:201` |
| `error` | ✘ | 指令拋出例外 | `cube.js:197`、`cube.js:218` |

λ-Cube 沒有 ITP 那個獨立的 `kernel` 狀態。核心丟出的例外在 `runScript()` 的 `try` 裡被接住（`cube.js:218`），狀態記成 `error`，但訊息裡會出現「核心」二字可以資辨認。

## 9.3.7 這一節怎麼用

寫 λ-Cube 腳本時記住三件事：**第一，`theorem` 的標頭可以跨行，但 `def`、`axiom` 的型別要寫在同一行**；**第二，`system` 指令決定了整個檔案能用哪些 Π 形式**，換系統之後所有宣告都要重新檢查；**第三，`apply` 遇到依賴型參數不是錯誤，是提醒**——它告訴你那個參數會出現在別的地方，請你手動寫出來。

λ-Cube 的 `check` 指令是這個系統最好的學習工具：任何時候不知道某個項是什麼型別，就 `check` 一下。核心的回覆從不說謊。
